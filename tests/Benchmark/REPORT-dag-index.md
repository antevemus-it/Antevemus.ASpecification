## Scenarios

- **large**: 200 partitions in 4 levels below the root, fan-out 5/3/3/3 (5 + 15 + 45 + 135), sibling partitions mutually disjoint, every entity routed to a leaf.
- **small**: 5 disjoint partitions in 1 level.
- **range** specifications: benchmark-local interval `[lo, hi)` with exact algebra, O(1) evaluation and O(1) disjunction.
- **library** specifications: `Spec::property('bucket', Spec::in(...))` (property access plus set membership; the large DAG has sets of 162, 54, 18 and 6 values, the small one sets of 162 values).
- Modes: **off** (no index: recursive walk of 1.4.4, `put()` tests every direct partition), **traversal** (subtree index, RN-06 (ii)), **full** (subtree index plus routing clusters, RN-06 (i)).
- `put()`: time to put every entity into a freshly built graph (the lazy index build is included). `findAll(all)`: `AlwaysTrueSpecification` over the loaded graph. `findAll(selective)`: the entities of one level-2 partition (one level-1 partition in the small DAG), pruning by disjunction applies.
- The results of every mode are compared (same entities, same order) before the numbers are kept.

## Verdict

Gates (RN-06), each over both kinds of specification, with a 5% noise margin for regressions:

- **Subtree index (RN-06 (ii))**: faster `findAll(all)` on the large DAG, and no operation slower on the small DAG.
- **Routing clusters (RN-06 (i))**: faster `put()` on the large DAG, and `put()` not slower on the small DAG.

## Cost of the routing clusters

Building the clusters of a node costs one `isDisjointWith()` pair (both directions) per pair of sibling partitions, once per graph (then maintained incrementally). The pair is O(1) for the range specifications, but for the library set specifications it grows with the product of the set sizes. One `isDisjointWith()` between two disjoint `Spec::property('bucket', Spec::in(...))` measured in this run:

| Values per set | One isDisjointWith() (ms) |
|---:|---:|
| 6 | 0.139 |
| 18 | 1.052 |
| 54 | 9.263 |
| 162 | 88.332 |

The evaluations the clusters save (about a third per `put()`, see the last column of the results) are worth far less than that one-time build on these workloads, so the clusters only pay off when the partition specifications have cheap disjunction or the graph receives a very large number of puts; the switch stays available for those cases.

**Subtree index (RN-06 (ii)): gate passed, enabled by default** (`PartitionRepository::setDagIndexEnabled(false)` turns it off).

**Routing clusters (RN-06 (i)): gate failed, disabled by default** (`PartitionRepository::setDagRoutingEnabled(true)` turns it on).
- no gain on library / large / put() (-278.8%)
- regression on library / small / put() (-551.4%, margin -5%)
