## [2.3.0] - 2026-10-18

A MINOR release with three roadmap milestones and one fix. **Wildcards and regular expressions that ignore case and accents** (milestone 22b, forward 039): `wildcard()` and `regex()` take the `TextComparison` that `contains()`, `startsWith()` and `endsWith()` took in 2.1.0, with the same answer in memory, in ALinq and in the databases that can give it, and refused where they cannot. **The validity window of a feature flag set through the service** (milestone 24d) and **percentage rollout** (milestone 24c), both in forward 040, through the audited path of `toggle()`: a reason, a compare-and-set on the row version and a history row in the same transaction. **#73** (BUG-20261018-WBPG), found while measuring the regular expressions of 22b: on PostgreSQL a `regex()` with `\b` or `\B` never matched. Three interfaces gain a parameter or methods (`IStringSpecificationFactory`, `ISqlAccentInsensitiveLike`, `IFeatureFlagStore`), which breaks a class that implements one of them directly (see *Changed*; no implementer outside the library was found in the consumers measured). Existing calls keep their answers, apart from the PostgreSQL regular expressions of #73, which now answer as memory does, and the two details declared under *Changed*. No new Composer dependency; the reference DDL of the flags gains three columns, read only when the store is told so, with the additive migration commented in it.

### Added

- **Wildcards and regular expressions that ignore case and accents** (Module 29, forward 039).
  - **Wildcard.** `Spec::wildcard(string $pattern, bool|TextComparison $caseSensitive = true)`, the DSL `matchesWildcardExpression()` and the factory `matchesWildcard()`, `like()` and `matchesWildcardExpression()`: `true` (the default) compares exactly, `false` is `IgnoreCase` (the rule of `wildcardIgnoreCase()`: both sides lowered with `mb_strtolower()` before `fnmatch()`), and `TextComparison::IgnoreCaseAndAccents` folds both sides with `foldCaseAndAccents()` (the pattern once, when the specification is built). `wildcardIgnoreCase()` and `matchesWildcardExpressionIgnoringCase()` stay as shortcuts of `IgnoreCase`. `WildcardSpecification` takes the comparison as its second constructor argument and gains `getComparison()`, `isCaseSensitive()` and `ignoresAccents()`; `getPattern()` returns the pattern as written. `WildcardExpressionMatcherIgnoreCaseStringSpecification` delegates to a `WildcardSpecification` with `IgnoreCase` instead of repeating it (it does not extend it, so a visitor that tests `instanceof WildcardSpecification` first never reads it as case-sensitive), with the same answers, and gains `getComparison()` (always `IgnoreCase`).
  - **Regular expression.** `Spec::regex(string $pattern, ?TextComparison $comparison = null)`, `Spec::matches()`, the DSL `matches()` and the factory `matchesRegex()`, `matchesRegularExpression()` and `matches()`: `null` (the default) keeps the pattern as written, as before, and so does `CaseSensitive`; `IgnoreCase` adds the `i` modifier (only `i`: to match non-ASCII capitals the pattern carries its own `u`); `IgnoreCaseAndAccents` matches `delimiter + foldAccents(body) + delimiter + modifiers ∪ {i, u}` against the candidate folded the same way. The body is never lowered, so every escape keeps its meaning (`\D` stays "not a digit", `\B` "not a word boundary"), and the author may write `/ção/` or `/cao/`. `RegexSpecification` takes the comparison as its second constructor argument and gains `getComparison(): ?TextComparison` and `ignoresAccents()`; with a comparison, `getPattern()`, `getBody()` and `getModifiers()` describe the pattern that is evaluated, so the `IgnoreCase` form goes through the existing translations (`~*`, `(?i)`, `REGEXP '(?i)…'`) unchanged.
  - **`TextComparison::foldAccents(string): ?string`**: the accent folding without the lowering (NFD, nonspacing marks removed, NFC), `null` for a text that is not UTF-8. `foldCaseAndAccents()` is now `mb_strtolower(foldAccents())`, with the same answers. As every `IgnoreCaseAndAccents` path, it requires `ext-intl` (`MissingExtensionException` otherwise).
  - **SQL**, through **`ISqlAccentInsensitiveLike::accentInsensitiveRegex(string $column, string $paramPlaceholder, string $foldedBody): ?ISqlWhereClause`** (`null` = refused, the default of `AbstractSqlDialect`). **PostgreSQL** translates both: the wildcard through `formatAccentInsensitiveLike()` (the glob becomes the `LIKE` pattern, both sides folded by the built-in expression), the regular expression as `<fold(col)> ~* :p`, the column folded by the same expression (or by the configured function, `f(lower(col))`) and the body bound with its accents folded in PHP and `\b`/`\B` written as `\y`/`\Y`. **MySQL 8.4 and MariaDB 11.4** translate the wildcard through the `utf8mb4_0900_ai_ci` collation of the 2.1.0 `LIKE` and **refuse the regular expression** (measured, see *Fixed*). Every other dialect refuses both with `NonTranslatableSpecificationException`, and a `PdoRepository` on those databases refuses the query unless `withInMemoryFallback()` was called. `SqlQueryVisitor` refuses any modifier other than `i`/`u` with `UnsupportedSqlOperationException`, as for a regular expression without a comparison, and translates `wildcard($p, false)` with the SQL of `wildcardIgnoreCase($p)`.
  - **TCriteria** refuses the accent folding, negated or not (`NonTranslatableCriteriaException`: `TFilter` concatenates the value, the reason given in 2.1.0); the wildcard with `IgnoreCase` becomes `UPPER() LIKE UPPER()`. **ALinq** evaluates the folded regular expression through the leaf, as the other folded leaves.
  - **Algebra.** A folded wildcard or regular expression is an opaque leaf (no subsumption between patterns); `equals()` tells the comparisons apart, and two bodies that fold the same (`/ção/` and `/cao/` with `IgnoreCaseAndAccents`) are the same leaf, since they answer the same. The soundness bench gains `wildcard('A*', false)` and `regex('/^A/', IgnoreCase)`, and, with `ext-intl`, `wildcard('*ação*', IgnoreCaseAndAccents)` and `regex('/^ac[aã]o$/', IgnoreCaseAndAccents)`.
- **`Contracts\Sql\ISqlRegexRewriter`** (`rewriteRegexBody(string $body): string`), separate from `ISqlDialect` so that external dialects keep compiling, as `ISqlPagination`: `SqlQueryVisitor` passes the body of every regular expression it translates through it when the dialect implements it. `PostgreSqlDialect` implements it (#73, under *Fixed*); `AbstractSqlDialect` does not, so every other dialect receives the body as written.
- **The validity window of a feature flag, through the service** (Module 30, milestone 24d, forward 040): `FeatureFlags::setValidity(string $code, ?DateTimeInterface $from, ?DateTimeInterface $until, string $reason, string|int|null $actor = null, string $origin = self::ORIGIN_UI, ?int $expectedVersion = null): FeatureFlagState`. Both bounds `null` clear the window; `from > until` is refused with `InvalidArgumentException` before the store is touched (the rule of the DDL's CHECK). One transaction with its history row, as `toggle()`, and a compare-and-set on the row **version** (`UPDATE … SET …, version = version + 1 WHERE code = :code AND version = :expected_version`), not on the switch: the window changes without turning the flag on or off. `$expectedVersion`, optional, is the version a screen read: a change made by someone else in between makes the save stale; `null` takes the version read inside the transaction.
- **Percentage rollout of a feature flag** (Module 30, milestone 24c): `FeatureFlags::setRollout(string $code, ?int $percent, string $reason, string|int|null $actor = null, string $origin = self::ORIGIN_UI, ?int $expectedVersion = null): FeatureFlagState` (0 to 100; `null` = no rollout, every subject), through the same audited path.
  - **The bucket.** A subject is in when `FeatureFlags::bucket($code, $subjectKey) < $percent * 100`. `bucket()` is `hexdec(first 8 hex digits of xxh3($code . "\0" . $subjectKey)) % FeatureFlags::ROLLOUT_BUCKETS` (10 000): public, so that a panel can explain an answer, stable between requests, processes and machines, and **part of the contract: changing it is a MAJOR** (Module 30 pins six golden values). Raising the percentage never takes a subject out; two flags give independent buckets.
  - **Evaluation order:** switch → validity window → (no subject list, no target and no rollout = `ENABLED`) → subject → subject list → target in code → rollout. With a rollout, a null subject, or one without a key, is `NOT_IN_TARGET`, and 100 % still needs a subject with a key. Inside the rollout the reason is `TARGETING_MATCH`; outside, the new **`FeatureFlagReason::OUTSIDE_ROLLOUT`** (`'outside_rollout'`; off; OpenFeature `DEFAULT`). `FeatureEnabledSpecification` keeps its signature; its failure carries the new reason and the bucket in its metadata.
- **`FeatureFlagChangeKind`** (`Toggle`, `Subject`, `Validity`, `Rollout`, stored as `toggle`, `subject`, `validity`, `rollout`). `FeatureFlagChange` gains `public readonly FeatureFlagChangeKind $kind` and `public readonly ?string $detail` (optional last constructor arguments: without a kind a row is `Subject` when it has a subject key and `Toggle` otherwise; a kind that contradicts the key is an `InvalidArgumentException`); `isSubjectChange()` is `kind === Subject`. The detail says what a window or rollout change set: `<from|open> → <until|open>` as UTC ISO-8601 (`2026-11-01T00:00:00+00:00`) or `cleared`; `none → 25%`, `25% → 50%`, `100% → none`. On such a row `oldEnabled`/`newEnabled` keep the switch, which did not change (`oldEnabled = null` when the row was created by that change).
- `FeatureFlagState` gains `?int $rolloutPercent` (last argument; outside 0..100 is an `InvalidArgumentException`); `FeatureFlagView` (`all()`) gains `validFrom`, `validUntil` and `rolloutPercent` (null without a row, or when the store does not keep them); `FeatureFlagEvaluation` gains `?int $bucket` and `?int $rolloutPercent`, added by `toMetadata()` as `bucket` and `rollout_percent` when present.
- **Stores.** `IFeatureFlagStore::supportsValidity()`, `compareAndSetValidity()`, `supportsRollout()` and `compareAndSetRollout()` (see *Changed*).
  - `InMemoryFeatureFlagStore` gains `bool $validity = true, bool $rollout = true` in its constructor, which mirror a PDO store without those columns (`put()` refuses a window or a rollout the store does not keep).
  - `PdoFeatureFlagStore` gains `FLAG_COLUMNS_SINCE_2_3` (`rollout_percent`), `CHANGE_COLUMNS_SINCE_2_3` (`change_kind`, `detail`) and **`COLUMNS_SINCE_2_3`**, the ready column map to pass as `columns:`; `canonicalColumns()` lists them. They are absent by default (see *Notes*).
  - The window needs `valid_from`, `valid_until` and `version` (mapped by default, as since 2.1.0); the rollout needs `rollout_percent` and `version`. A store without them answers `false` in `supportsValidity()`/`supportsRollout()`, and the service refuses the change with a `FeatureFlagStoreException` that names the columns, before opening a transaction.
  - `change_kind` is read case-insensitively and trimmed: `NULL` or empty is `toggle`, `toggle` with a subject key is `subject` (a row written before 2.3.0, after the migration), an unknown value or one that contradicts the key is a `FeatureFlagStoreException`. `rollout_percent` is read strictly (an integer from 0 to 100 or `NULL`; anything else is a `FeatureFlagStoreException`, so the evaluation is `ERROR`, fail closed).
- **`resources/sql/feature_flags.ansi.sql`**: `feature_flag.rollout_percent SMALLINT` (CHECK 0..100), `feature_flag_change.change_kind VARCHAR(20) DEFAULT 'toggle' NOT NULL` (CHECK of the four values) and `feature_flag_change.detail VARCHAR(400)`. The header documents them and carries, commented, the **additive migration 2.1.0 → 2.3.0** for an existing table: three `ALTER TABLE … ADD COLUMN` with the CHECK inline (SQLite has no `ADD CONSTRAINT`) and one `UPDATE` that marks the subject rows; tested on SQLite, PostgreSQL 17, MySQL 8.4 and MariaDB 11.4.
- **Tests.** Module 29 (entity `Module29AccentRow`; PHPUnit bridge `WildcardRegexAccentInsensitiveModuleTest`) and Module 30 (`Module30Unit`, `Module30SpyStore`; bridge `FeatureFlagsIIModuleTest`; fixture `tests/Fixtures/feature_flags/feature_flags_2_1_0.ansi.sql`, the exact DDL of 2.1.0, for the migration test) in the runner, in PHPUnit, in `run_portability.sh` and in `run_parity_suites.sh`, so that the `SQL parity` CI job runs them against PostgreSQL 17, MySQL 8.4 and MariaDB 11.4. Module 12 gains the reproduction of #73. `Module27ProbeStore` implements the four new store methods by delegation, and the exhaustive table of reasons of Module 27 gains `OUTSIDE_ROLLOUT` (no assertion relaxed).

### Changed

- **`IStringSpecificationFactory`** (and so `Spec`, the DSL functions, `AbstractStringSpecificationFactory`, `StringSpecificationOperationsTrait` and `SpecificationFactory`): `matchesRegex()`, `matchesRegularExpression()` and `matches()` take `?TextComparison $comparison = null`; `matchesWildcard()` and `like()` take `bool|TextComparison $caseSensitive = true` (and so does the trait's `matchesWildcardExpression()`). The abstract methods of `AbstractStringSpecificationFactory` are `matchesRegex(string, ?TextComparison = null)` and `matchesWildcard(string, bool|TextComparison = true)`, and its aliases pass the argument on. **Breaking for** a class that implements the interface directly, or that extends the abstract factory (it must declare the new parameter in `matchesRegex()` and `matchesWildcard()`), as in 2.1.0. No implementer outside the library was found in the consumers measured.
- **`ISqlAccentInsensitiveLike`** gains `accentInsensitiveRegex()`. **Breaking for** a dialect that implements the interface directly; one that extends `AbstractSqlDialect` inherits `null` (refused).
- **`IFeatureFlagStore`** gains `supportsValidity(): bool`, `compareAndSetValidity(string $code, int $expectedVersion, ?DateTimeImmutable $from, ?DateTimeImmutable $until, DateTimeImmutable $at, string|int|null $actor): bool`, `supportsRollout(): bool` and `compareAndSetRollout(string $code, int $expectedVersion, ?int $percent, DateTimeImmutable $at, string|int|null $actor): bool`. **Breaking for** a store implemented outside the library; none was found (the production consumer measured uses a flag service of its own, not this interface).
- **A regular expression built with a `TextComparison` must be delimited** (`/…/`, `#…#`): `Spec::regex('^a', TextComparison::IgnoreCase)` is refused with `InvalidArgumentException`, and so is a body that is not UTF-8 with `IgnoreCaseAndAccents`. `regex()` without the comparison is unchanged.
- **The new flag changes refuse what changes nothing**: setting the window or the percentage that is already there, or clearing what is already empty, throws `StaleFeatureFlagException` and writes nothing, as `toggle()` to the state the flag is already in (no `50% → 50%` row in the history). Both require a declared flag (`UndeclaredFeatureFlagException`), as turning on does; a declared flag without a row gets one, off, on its first change.
- **`InMemoryFeatureFlagStore::put()` of a state without a version stores version 1**, the default of the DDL. **Before → after:** `find($code)->version` of a seeded row `null` → `1`. `toggle()` already incremented the version on both stores and is unchanged (it stays a compare-and-set on the switch); that increment makes a window or a rollout read before it stale. Subject changes keep their compare-and-set on the presence in the list and do not increment the version.
- **`wildcard($p, false)` is `wildcardIgnoreCase($p)`**, in memory, in SQL and in TCriteria. PHP ignored a second argument given to `Spec::wildcard()` in 2.2.0, so such a call answered case-sensitively; it now ignores case. **Before → after:** `Spec::wildcard('a*', false)->isSatisfiedBy('Abc')` `false` → `true`.
- A visitor of your own that reads every `WildcardSpecification` as case-sensitive, or uses the `getPattern()` of a `RegexSpecification` without folding the candidate, translates the new leaves wrongly: read `getComparison()`/`ignoresAccents()` first (the warning 2.1.0 gave for the literal leaves; it is in the docblocks).

### Fixed

- **`regex()` on PostgreSQL sent PCRE's word boundaries as written, so they never matched (#73, BUG-20261018-WBPG).** In PostgreSQL's regular expressions (ARE) `\b` is a backspace and `\B` a synonym of the backslash; the word boundaries are `\y` and `\Y`. `SqlQueryVisitor::translateRegex()` bound the PCRE body as it was, so `Spec::regex('/\bfoo/')` selected no row on PostgreSQL, without an error, where memory accepted rows. The body of every regular expression translated for PostgreSQL (without a comparison, with `IgnoreCase` and with `IgnoreCaseAndAccents`) now goes through `PostgreSqlDialect::rewriteRegexBody()` (`ISqlRegexRewriter`): `\b` → `\y` and `\B` → `\Y` outside a bracket expression; bracket expressions (`[\b]` is a backspace in both), their POSIX classes (`[:alpha:]`) and `\Q…\E` quotations are kept, and so is every other escape. The SQL is unchanged; only the bound parameter changes, and only on PostgreSQL. **Before → after**, for `Spec::toSql(Spec::property('df', Spec::regex('/\bconfigura\w+/')), 'pgsql')`: SQL `("df" IS NOT NULL AND "df" ~ :p1)` → the same; parameter `\bconfigura\w+` → `\yconfigura\w+`; rows found on PostgreSQL 17.11 over the values of Module 29 `[]` → `['configuracao']`, as in memory. Found by the measurement of forward 039 (12 of the 30 differences of the regular expressions on PostgreSQL); no consumer measured compiles `regex()` to SQL.
- **Measured limits, documented in the dialects and checked as positive controls in Module 29.** They are not defects of this release, and the in-memory answer is not bent to hide them:
  - **The regular expression without accents is refused on MySQL and MariaDB**: their regular expression engines (ICU on MySQL, PCRE2 on MariaDB) ignore the collation of the column, so `^cora[cç][aã]o$` over a column converted to `utf8mb4_0900_ai_ci` finds `coracao` and not `Coração`. Every form measured differed from memory, with the body folded or as written: MySQL 8.4 with `REGEXP_LIKE(col, :p, 'i')` and `REGEXP '(?i)…'` (54 to 60 of 240 queries), MariaDB 11.4 with `REGEXP '(?i)…'` (51 to 57 of 240). Neither database has a Unicode normalization function to fold the column.
  - **On PostgreSQL the class shorthands keep the classification of the database**, in every `regex()`, with a comparison or without: `\d` is the ASCII digits only (PCRE with `u` also takes the other decimal digits, 360 code points of the BMP, so `١٢٣` matches `\d` in memory and not on PostgreSQL), `\w` and `\s` differ from PCRE on 605 and 5 code points of the BMP (`²`, `½`, spacing marks of Indic scripts, no-break spaces), `.` matches a newline, and a column with the `"C"` collation classifies only ASCII letters as `\w`. #73 covers the word boundaries only.
  - **`fnmatch()` and multibyte text** (every `wildcard()`, since 1.0): under glibc's `C.UTF-8` the `?` does not always stand for one character (`fnmatch('??', 'é')` is `true`, `fnmatch('??', 'か')` is `false`). With `IgnoreCaseAndAccents` the accented letters fold to one ASCII byte, so the difference stays with the letters that do not fold (`ß`, `æ`, CJK, Hangul). The wildcard on MySQL/MariaDB keeps the measured limits of the 2.1.0 `LIKE` (`ø`, `ł`, `ð`, `й`, kana).
- A message of `PdoFeatureFlagStore` read "has no a subject key"; it reads "needs a subject key" (found by the mutation tests of forward 040).

## [2.2.0] - 2026-10-18

A MINOR release that closes the two decisions the soundness bench of 2.1.0 left pending (roadmap milestone 26b, forward 038). The bench had found that the algebra and the evaluation disagreed; in one case the evaluation was wrong (a typed default value accepted `null`), in the other the candidate was (`NAN` has no order). Two answers change, declared under *Changed*; no public signature changes, no new dependency.

### Changed

- **A typed default value refuses `null` (#68, BUG-20261013-JPQT).** `DefaultValueSpecification` with a type (`isBlankString()`/`blankString()`, `defaultNumber()`, `defaultValueOfType()`, `isDefaultValueOfType()`, the DSL functions of the same names) accepted `null` besides the default value of its type, as Domian's does, so `isBlankString()` and `defaultNumber()`, which the algebra declares disjoint, shared a candidate. The decision (maintainer, 2026-10-18) is that a typed default is *"a value of that type, and its default"*: `isBlankString()` is "a text that is empty or whitespace", `defaultNumber()` "a number that is zero", `defaultValueOfType('bool')` `false`, `('array')` `[]`, as `default(T)` of a non-nullable type under `strict_types`; `null` is the default of *some* type, so only the untyped `defaultValue()` keeps accepting it (as `default(T?)` does). With that, the disjointness of two typed defaults of different types is true for every candidate, the untyped default is disjoint with none of them, and `simplify()` keeps proving `and(isBlankString(), defaultNumber())` a contradiction. Three assertions of the Domian Parity suite that asserted `null` as blank or as zero are inverted with a note, as the seven of 2.1.0; `blankString ⟂ zero` stays `true`. **Before → after:** `Spec::isBlankString()->isSatisfiedBy(null)` `true` → `false`; `Spec::defaultNumber()->isSatisfiedBy(null)` `true` → `false`; `Spec::defaultValue()->isSatisfiedBy(null)` `true` → `true`.
- **`NAN` is refused by the ordered leaves, as a candidate and as a bound (#70, BUG-20261013-XEIB).** `NAN < v`, `NAN > v` and `NAN == v` are all `false`, so `not(lessThan(5.5))` accepted `NAN` and its inversion `greaterThanOrEqualTo(5.5)` did not, and `simplify()` or De Morgan could change the answer for it. `greaterThan()`, `greaterThanOrEqualTo()`, `lessThan()` and `lessThanOrEqualTo()` (and what is built on them: `property()`, `not()`, the ALinq predicate, which delegates to the leaf) now raise `IncompatibleTypeException` for a `NAN` candidate, as they do for a text against a number, with a message that says why, and `InvalidArgumentException` for a `NAN` bound (`Spec::lessThan(NAN)` ordered nothing: it accepted no candidate and its inversion every one). `INF` stays an ordered number. The inversion of every numeric leaf is kept; `TypeCompatibility::isOrderable()` answers `false` for `NAN`, so the interval rules of the algebra make no promise about such a bound; `equalTo()`, `notEqual()` and `in()` keep answering `NAN` (it is equal to nothing, consistently with their inversion), and so does `defaultNumber()` (`NAN` is not zero). `NAN` joins the candidate pool of the bench (`AlgebraSoundnessTest`), which now checks every promise on it. **Before → after:** `Spec::not(Spec::lessThan(5.5))->isSatisfiedBy(NAN)` `true` → `IncompatibleTypeException`; `Spec::greaterThanOrEqualTo(5.5)->isSatisfiedBy(NAN)` `false` → `IncompatibleTypeException`; `Spec::lessThan(NAN)` a leaf that accepts nothing → `InvalidArgumentException`.
- `IncompatibleTypeException` accepts an optional explicit message as its fourth constructor argument (the three public properties are unchanged); `TypeCompatibility::isUnordered()` and `assertOrderableBound()` added.

No public signature changes; the `TCriteria` rendered for a specification whose root is a disjunction gains one pair of parentheses (declared under *Changed*).

### Fixed

- **A specification compiled to `TCriteria` leaked soft-deleted rows and rows of other units when its root was a disjunction (BUG-20261013-4CLQ, #72).** `Spec::toCriteria()`, `TCriteriaBuilder` and `CriteriaSpecificationVisitor::buildCriteria()` returned, for `or()`, `anyOf()`, `not(and())`, a negated comparison (`col IS NULL OR ...`) or an `in()` holding `null`, a `TCriteria` whose top-level operator was `OR`. Adianti's `TRepository::load()`, `count()`, `update()` and `delete()` add the soft delete filter (`DELETEDAT`) and the `PREFILTERS` of the model (`{session.userunitid}`) to the **same** object with `add(..., AND)`, and `TCriteria::dump()` does not group what is already there, so the effective criteria was `a OR b AND deleted_at IS NULL AND (unit_id = 1)` = `a OR (b AND ...)`: the filters restricted only the last branch. Measured with the real classes of Adianti 8.7.0 on SQLite: `load()` returned 100 rows where 40 were expected, `count()` 100, a soft `delete()` marked 100 rows, and 121 of 400 generated trees leaked under an `AND` filter. The root is now nested in a criteria of its own whenever its top level is `OR`, so `add($filter)` yields `((a OR b) AND filter)`; a root whose top level is `AND`, or a single filter, is returned as before, with the same SQL. `limit`, `offset`, `order`, `direction` and `group` set by `TCriteriaBuilder` are preserved. Guarded by a reproduction over 13 root shapes × 7 public paths × the `add()` of `TRepository` and `mergeCriteria()`, a property test over 400 generated trees and 320 boundary rows (seed 20261013; the previous code leaked in 121 of them), and a run against the real Adianti classes in a child process (prepared and unprepared `TFilter`), skipped with a notice when the framework is not beside the library, as in CI. The Adianti stub of the suite gains `mergeCriteria()`, `__clone()` and `getPreparedVars()` copied from the framework. **Before → after:** `Spec::toCriteria(Spec::property('n', Spec::equalTo(1))->or(Spec::property('n', Spec::equalTo(5))))->dump()` `(n = 1 OR n = 5)` → `((n = 1 OR n = 5))`; after `TRepository` adds its filters, `(n = 1 OR n = 5 AND deleted_at IS NULL AND (unit_id = 1))` → `((n = 1 OR n = 5) AND deleted_at IS NULL AND (unit_id = 1))`.

### Changed

- **The `TCriteria` rendered for a disjunction at the root carries one more pair of parentheses** (`(X)` → `((X))`), the consequence of the fix above. Only the text of `dump()` and of the prepared form changes; the rows selected are the ones the in-memory evaluation selects, now also after the caller adds conditions. A test that compares that text literally needs the outer pair (28 assertions of this suite did; each carries a comment naming #72). `Spec::toSql()` and `PdoRepository` are unchanged: their compiler already parenthesised every composite.

## [2.1.0] - 2026-10-13

A MINOR release, additive apart from the answer changes declared under *Changed* and *Fixed*. Three additions: **declared feature flags** with targeting and an audit trail (roadmap milestone 24, forward 034), **text comparison that ignores case and accents** as an explicit option, with the same answer in memory, in ALinq and in SQL (milestone 22, forward 035), and a **soundness bench of the specification algebra** (milestone 26, forward 037), which checks every promise of the algebra (`equals()`, subsumption, disjointness, tautology and contradiction, `simplify()`, the deduplication of `and()`/`or()`, partitions) against the evaluation, by brute force over every concrete specification class of the library. The bench and the investigation behind it found the defects listed under *Fixed*: in each one the algebra promised more than the evaluation delivers, so `simplify()`, a partition lookup or a deduplicated composite could change an answer. The rule applied is that **the algebra never promises more than the evaluation delivers**: where they disagreed, the algebra now promises less (a simplification that is lost is acceptable, a wrong answer is not), except for date-times, where the in-memory evaluation of `equalTo()`/`notEqual()`/`in()` now compares by instant, as SQL and the rest of the library already did. One interface gains a parameter type and a method (`IStringSpecificationFactory`), which breaks a factory that implements it directly (see *Changed*). No new Composer dependency: `ext-intl` is suggested, and only the new accent-insensitive option needs it.

### Added

- **Declared feature flags** (`Antevemus\ASpecification\FeatureFlags`, Module 27). A flag is declared in code and switched in the database; every flag is born off.
  - **Declaration.** `FeatureFlagDefinition` (immutable): `code` (`^[a-z][a-z0-9_]{2,79}$`), `name`, `description`, `category`, `audience`, `impactOn`, `impactOff` (what the confirmation says when turning it on and off), `origin` (the task or release that created it), an optional `target` (an `ISpecification` over the subject) and an optional `subjectKey` (the property path of the subject key, read through the shared accessor). `FeatureFlagRegistry` is the one place where flags are declared: an invalid or duplicate code is refused, the declaration order is kept, and `fromArray()` takes an application's own registry array as it is (an unknown key is refused, so a typo never drops a text).
  - **Evaluation** (`FeatureFlags`, the service over a registry and a store): `isEnabled($code, $subject = null)`, `evaluate()` (a `FeatureFlagEvaluation` with the value, the reason, the subject key and the error, `toMetadata()`) and `spec($code)`, a `FeatureEnabledSpecification` that composes with any specification (`$flags->spec('renewal_notice')->and($dueSoon)`) and whose failure carries the reason in its metadata. A flag is on when its switch is on **and** the reference instant is inside its validity window (`valid_from`/`valid_until`, both inclusive, a date-only bound covering the whole day; `withAsOf()` evaluates at another instant) **and** the subject is in its target: the subject list stored with the flag (empty = no restriction; a string or integer subject is the key itself, an object or array is read through `subjectKey`) and the specification declared in code. With a target, a null subject is not in it. A code that is not declared is off, with the reason `UNKNOWN_FLAG`, whatever the database says; reading never throws.
  - **Fail closed, never silent.** When the store cannot be read (no table, no connection) or the target cannot be evaluated, the flag is off with the reason `ERROR` and the exception goes to an optional `IFeatureFlagErrorReporter` (`InMemoryFeatureFlagErrorReporter` for tests), once per load; `evaluate()->error` and `lastError()` keep it for a settings screen, and an exception of the reporter is ignored. `FeatureEnabledSpecification` reports such a flag as a plain failure with the reason `error` (never an evaluation error), so `not()` sees it off, and its metadata carry the class of the exception, never its message.
  - **One load per instance**: the state of every flag and the subject lists are read on the first evaluation (one query on PDO: flags `LEFT JOIN` subjects) and kept; `refresh()` reads again, and every change made through the instance refreshes it.
  - **Changes**, each in one transaction of the store together with its history row: `toggle($code, bool $enable, string $reason, $actor = null, string $origin = FeatureFlags::ORIGIN_UI)` (returns the state after the change), `addSubject()` and `removeSubject()` (same arguments, with the subject key). The reason is required: whitespace runs collapsed, 10 to 1 000 characters by default (configurable; `InvalidFeatureFlagReasonException`). Each change is a compare-and-set (turning on expects off, adding a subject expects it absent...): a stale change throws `StaleFeatureFlagException` and writes nothing. Turning on, or adding a subject to, a flag that is not declared throws `UndeclaredFeatureFlagException` (it would have no effect); turning off and removing subjects stay allowed, to clean up an orphan row. A declared flag without a row gets one, off, on its first change (its history row says `oldEnabled = null`). The origin is the caller's text (`ORIGIN_UI`, `ORIGIN_MIGRATION`, `ORIGIN_SCRIPT` for convenience) and the actor `string|int|null`; who may change a flag is a decision of the application.
  - **Listing**: `all()` (`FeatureFlagView`: the union of the registry and the store in registry order, the texts of the code winning, a flag found only in the database listed as not declared, with its state, subjects and last change) and `history(?string $code = null, int $limit = 50)` (`FeatureFlagChange`, most recent first; switch changes and subject changes in the same trail).
  - **`FeatureFlagReason`** (`ENABLED`, `TARGETING_MATCH`, `DISABLED`, `NOT_IN_TARGET`, `OUTSIDE_VALIDITY`, `UNKNOWN_FLAG`, `ERROR`) with its documented mapping to the evaluation reasons and error codes of OpenFeature (`toOpenFeatureReason()`, `toOpenFeatureErrorCode()`), so that an OpenFeature provider can be written over the service later without changing it.
  - **Stores**: `IFeatureFlagStore`, `InMemoryFeatureFlagStore` and `PdoFeatureFlagStore`, which run the same contract battery (SQLite in the suite; PostgreSQL 17, MySQL 8.4 and MariaDB 11.4 through `run_portability.sh`). `PdoFeatureFlagStore` reads the reference tables by default and existing tables where they are: table names by role (`flag`, `change`, `subject`; `subject => null` when the database keeps no subject lists), column names by role (canonical => real; `null` = that table does not have the feature, such as a validity window or a version), the optional `created_*`, `updated_*` and `deleted_at` columns (stamped when mapped; a row with `deleted_at` set is neither read nor changed), fixed values that select the flag rows of an audit table shared with other trails (`$changeScope`), the storage of each Boolean column (`BooleanStorage`, or a pair of texts such as `['true', 'false']`, read strictly: any other stored value is a `FeatureFlagStoreException`), the format and time zone of the instants, and a history key generated by the database. Identifiers are validated, values always bound; a missing row is created by "check, then insert" (under a savepoint on PostgreSQL, so a lost race does not abort the caller's transaction); `withQueryLogger()` as in `PdoRepository`. Exceptions: `FeatureFlagException` (base), `FeatureFlagStoreException`, `StaleFeatureFlagException`, `UndeclaredFeatureFlagException`.
- **`resources/sql/feature_flags.ansi.sql`**: `feature_flag` (the switch, `CHAR(1)` `'Y'`/`'N'` `DEFAULT 'N'`, the validity window, who turned it on and off last, a version), `feature_flag_change` (the append-only history: the library never updates nor deletes it; ULID key) and `feature_flag_subject` (the subject lists, `ON DELETE CASCADE`); portable SQL, `CREATE TABLE IF NOT EXISTS`, instants as fixed-width UTC text, and an optional PostgreSQL trigger, commented out, that makes the history append-only in the database too.
- **Text comparison that ignores case and accents** (Module 28). `TextComparison` (`CaseSensitive`, `IgnoreCase`, `IgnoreCaseAndAccents`) is accepted wherever the case flag of a text operator was: `Spec::contains()`, `startsWith()`, `endsWith()`, the DSL functions of the same names and the factory (`bool|TextComparison $caseSensitive`; `true` is `CaseSensitive`, `false` is `IgnoreCase`, so no existing call changes meaning, named arguments included). The equality pair: `Spec::equalIgnoreCaseAndAccents()` (factory `equalIgnoringCaseAndAccents()`, class `EqualIgnoreCaseAndAccentsStringSpecification`). `Spec::contains('configuracao', TextComparison::IgnoreCaseAndAccents)` accepts `Configuração`.
  - **In memory and in ALinq**, both sides are folded the same way: canonical decomposition (NFD), removal of the nonspacing marks (`\p{Mn}`), canonical composition (NFC) of what is left, `mb_strtolower()`. `ç`, `ã`, `é`, `ñ`, `ü` fold to their base letter; letters that are not a base letter plus a mark stay themselves (`ß` is not `ss`, `æ` is not `ae`, `œ`, `ø`, `đ`, `ł` stay distinct), as .NET's `CompareOptions.IgnoreNonSpace`.
  - **`ext-intl` is required by this option only** (the `Normalizer` class; a polyfill is not accepted): without it, building a specification with `IgnoreCaseAndAccents` throws the new `Specifications\Exceptions\MissingExtensionException` (with `$extension`), which names the extension. Nothing else needs it.
  - **SQL**, through the new `Contracts\Sql\ISqlAccentInsensitiveLike` (`formatAccentInsensitiveLike()`, separate from `ISqlDialect` so that external dialects keep compiling, as `ISqlPagination`). **PostgreSQL**: both sides of the `LIKE` folded by an expression equal to the in-memory folding, `lower(normalize(regexp_replace(normalize(x, NFD), <marks>, '', 'g'), NFC))`, which needs no extension and is `IMMUTABLE` (measured on PostgreSQL 17: the 50 303 letters and marks of the BMP fold as in memory under the default collation); `new PostgreSqlDialect('unaccent')` (or the name of an `IMMUTABLE` wrapper) uses a database function instead, and `PostgreSqlDialect::builtInAccentFolding('t')` gives the body of such a wrapper. **MySQL 8.4 and MariaDB 11.4**: `CONVERT(col USING utf8mb4) COLLATE utf8mb4_0900_ai_ci LIKE :p` (`new MySqlDialect('utf8mb4_uca1400_ai_ci')` for MariaDB 10.10 to 11.4.4). **Refused** with `NonTranslatableSpecificationException`, never answered differently from memory: SQL Server and Oracle (measured: their accent-insensitive collations equate `ß` with `ss` and `æ` with `ae`), SQLite, DuckDB, Db2, Informix, Firebird and ANSI; a `PdoRepository` on those databases refuses the query unless `withInMemoryFallback()` was called. **TCriteria** refuses it (`NonTranslatableCriteriaException`): Adianti's `TFilter` concatenates the value it receives, so the folding cannot be applied to it safely. The `LIKE` escaping of 1.14.0 is unchanged. Parity measured with a pt-BR, es, fr and de battery and the limits: PostgreSQL 17 (351 queries), MySQL 8.4 (221) and MariaDB 11.4 (405).
  - `TextComparison::of()`, `isCaseSensitive()`, `ignoresAccents()`, `isAccentFoldingAvailable()`, `assertAccentFoldingAvailable()`, `foldCaseAndAccents()`; `PostgreSqlDialect::getAccentFoldingFunction()`, `MySqlDialect::getAccentInsensitiveCollation()`. The PostgreSQL expression strips the 346 ranges (1 985 code points) of `\p{Mn}` of PCRE2 10.40 and 10.44 (PHP 8.2 and 8.4); the module suite checks that every `\p{Mn}` of the running PCRE is covered.
- **Soundness bench of the specification algebra** (`tests/PhpUnit/AlgebraSoundnessTest.php`, forward 037). A pool of over 700 specifications that covers every concrete specification class of `src/` (comparison, `in`, nulls, text with the three `TextComparison` cases, date-times, value objects, collections and entities, method calls, `looselyEqualTo()`, the wrappers of `a()`/`an()`/`isA()`/`isAn()`, user subclasses with predicates of their own, annotated variants) and generated composites (`and`, `or`, `not`, `nor`, property restrictions; fixed seed), checked pair by pair against about 80 boundary candidates (distinct instances of the same value, the same instant in other zones and classes, `'1'`/`1`/`true`, `null`, fractions, accents, entities of sibling types) for every promise listed above. A guard fails when a concrete specification class is missing from the pool, so a new leaf cannot ship outside it. The fixed part runs in the default PHPUnit suite in about 10 seconds; `ASPEC_SOUNDNESS_EXTENDED=1` widens it (about 3 million pairs, no violation) and `ASPEC_SOUNDNESS_DUMP=<file>` writes the violations as JSON lines. `AlgebraSoundnessCasesTest` keeps one reproduction per defect fixed below and watches the two planned for 2.2.0; `DateSqlParityTest` compares memory and SQL for the date-time leaves (SQLite in the suite; PostgreSQL 17, MySQL 8.4 and MariaDB 11.4 through `run_portability.sh`).

### Changed

- **`equalTo()`, `notEqual()` and `in()` compare date-times by instant** (#59, BUG-20261013-LIZI). In memory they compared a `DateTimeInterface` by identity (`===`, strict `in_array()`), while the relational leaves, `at()`, the algebra of `in()` and the generated SQL (`"d" = :p1`) compare by value, so the same specification accepted a row in the database and refused the same value hydrated in memory (with `withInMemoryFallback()`, or when an entity read back was evaluated again). They now compare the instant, whatever the class (`DateTime`, `DateTimeImmutable`, a subclass) and the time zone; objects that are not date-times are still compared by identity. **Before → after**, for `$b` a distinct instance at the same instant as `$a` (a clone, another zone or the other class): `Spec::equalTo($a)->isSatisfiedBy($b)` `false` → `true`; `Spec::notEqual($a)->isSatisfiedBy($b)` `true` → `false`; `Spec::in([$a])->isSatisfiedBy($b)` `false` → `true`; `specify(DateTime::class)->isDisjointWith(Spec::equalTo($immutable))` `true` → `false`, and their conjunction, which threw, is built. `equals()` and the algebra of the equality points follow (date-times by instant; a set of `in()` compared as a set).
- **`calling()` hands each date-time argument to the method in the default time zone of PHP** (#60, BUG-20261013-Y4LG): a copy of the same class at the same instant, in `date_default_timezone_get()`, whatever zone it was declared in. `equals()` already compared those arguments by instant (forward 018 RN-04), so `calling('day', [$utc], ...)` equaled `calling('day', [$saoPaulo], ...)` while a method that reads the local date answered differently. **Before → after**: a method that formats its argument (`$d->format('Y-m-d')`) received the zone of the declaration → it receives the default zone; two calls whose arguments denote the same instant now answer the same.
- **`IStringSpecificationFactory`** (and so `Spec`, the DSL functions, `AbstractStringSpecificationFactory` and `StringSpecificationOperationsTrait`): `contains()`, `startsWith()` and `endsWith()` take `bool|TextComparison $caseSensitive`, and the interface gains `equalIgnoringCaseAndAccents(string $value): ISpecification`. **Breaking for** a class that implements the interface directly (it must widen the three parameters and add the method) or that extends the abstract factory and overrides one of those methods with `bool` (PHP refuses the narrower parameter). A factory that extends `AbstractStringSpecificationFactory` without overriding them inherits everything. No implementer outside the library was found in the consumers measured.
- **`SqlDialectFactory::createPaginating(ISqlDialect|SqlDialect|string $dialect, string $consumer): ISqlDialect&ISqlPagination`** resolves a dialect for a consumer whose reads rely on `LIMIT` and refuses, with `UnsupportedSqlOperationException`, one that does not implement `ISqlPagination` (#56). `PdoTriggerStateStore`, `PdoDomainEventOutbox` and `PdoMachineSchema` hold their dialect as `ISqlDialect&ISqlPagination` and resolve it through it, in their constructor (see *Fixed*). Every dialect of the library paginates, so nothing changes with them.
- **`composer.json` `suggest`: `ext-intl`**, for `TextComparison::IgnoreCaseAndAccents`.

### Fixed

Every item below was found by the investigation of 2026-10-12/13 or by the soundness bench, has its reproduction in the suite, and was checked to fail on 2.0.0 and to pass on 2.1.0, each fix alone against its own reproduction. Unless an item says otherwise, no evaluation of a leaf changes: what changes is what the algebra proves (`equals()`, `isGeneralizationOf()`/`isSpecialCaseOf()`, `isDisjointWith()`, `isTautology()`/`isContradiction()`) and, through it, what `simplify()`, the deduplication of `and()`/`or()` and the partition lookup do.

- **`equals()` ignored the private state of ancestor classes** (#55, BUG-20261012-KEUQ). It compared the properties reflection returns for the concrete class, which leave out the `private` properties declared by its parents; `contains()`, `startsWith()` and `endsWith()` keep their literal and comparison there since 1.4.0, so any two of the same kind were "equal". **Before → after**: `Spec::contains('a')->equals(Spec::contains('b'))` `true` → `false`; `Spec::simplify(Spec::contains('a')->and(Spec::contains('b')))->isSatisfiedBy('a')` `true` → `false` (the tree answers `false`); `a OR NOT b` was simplified to `alwaysTrue()` and `a AND NOT b` to `alwaysFalse()` (and proven a tautology and a contradiction) → kept; `(a AND x)->and(b AND y)` dropped its second operand → keeps both; a partition on `name ~ 'b'` replaced the one on `name ~ 'a'` and `findPartition()` returned the wrong one → distinct. `equals()` now walks the class chain up to `AbstractSpecification` (each slot read through the class that declares it; static properties left out; `because()`/`withCode()` still compared).
- **PDO stores dropped `LIMIT` in silence with a dialect outside the library** (#56, BUG-20261012-2ESW). `PdoTriggerStateStore::findSatisfied()`, `PdoDomainEventOutbox::fetchPending()` and `PdoMachineSchema::limit()` (behind `findDue()` and the effect outbox) applied the limit only when the dialect was an `AbstractSqlDialect`, and otherwise ran the scan without any limit, without notice. **Before → after**: a dialect implementing only `ISqlDialect` → unbounded scan; now → refused when the store is built, with `UnsupportedSqlOperationException`. Not reachable with the constructors of 2.0.0, which always build a dialect of the library; the type now says what the code needs.
- **`equals()` of `AllEntitiesSpecification` and `UniqueEntitySpecification` ignored `because()`/`withCode()` and accepted any subclass** (#57, BUG-20261013-7RQV). Both overrode `equals()` with their own state only and `instanceof self`, and `UniqueEntitySpecification` treated `IEntity::class` as a wildcard inside `equals()` (equality was not transitive). **Before → after**: `(new AllEntitiesSpecification())->withCode('X')->equals((new AllEntitiesSpecification())->withCode('Y'))` `true` → `false`; `(new UniqueEntitySpecification(1))->because('a')->equals((new UniqueEntitySpecification(1))->because('b'))` `true` → `false`; `simplify(U(1, Customer) OR U(1))` refused `Order#1` → accepts it; `U(1, Customer) AND U(1, Vip)` became `alwaysFalse()` → kept; a partition on `U(1)` was replaced by one on `U(1, Customer)` → distinct. Both now use the structural `equals()`; the `IEntity` wildcard moved to subsumption.
- **`equals()` compared value objects loosely** (#58, BUG-20261013-2DAZ). Two objects that are not specifications were equal when `$a == $b` (`'1' == 1`, `null == false`), while `equalTo()` compares such objects by identity. **Before → after**, with `final class Money { public function __construct(public $amount) {} }`: `Spec::equalTo(new Money('1'))->equals(Spec::equalTo(new Money(1)))` `true` → `false`; for `$c = new Money(1)`, `Spec::simplify(Spec::equalTo(new Money('1'))->or(Spec::equalTo($c)))->isSatisfiedBy($c)` `false` → `true` (the tree answers `true`). Objects that are not date-times are compared by identity in `equals()` and in the algebra of the equality points; date-times by instant (see *Changed*).
- **The algebra proved subsumption for the null candidate that composites refuse** (#61, BUG-20261013-FEIT). `AND`, `OR`, `NOT`, `NOR` and property restrictions refuse `null`, some leaves accept it, and the algebra ignored the difference. **Before → after**: `Spec::notIn(1, 2)->isGeneralizationOf(Spec::isNull())` `true` → `false`; `Spec::isNotNull()->isGeneralizationOf(Spec::isNull())` `true` → `false`; the same for `notEqual(5)` over `equalTo(null)` and `not(not(isNull()))` over `isNull()`; `not(isNotNull())` is no longer rewritten as `isNull()` nor `not(in())` as `alwaysTrue()`.
- **`looselyEqualTo()` inherited the strict algebra** (#62, BUG-20261013-NZ2V). Its subsumption, disjointness and inversion were those of `equalTo()`. **Before → after**: `Spec::simplify(Spec::equalTo(1)->and(Spec::looselyEqualTo('1')))->isSatisfiedBy(1)` `false` → `true` (the tree answers `true`); `Spec::looselyEqualTo(1)->isDisjointWith(Spec::looselyEqualTo('1'))` `true` → `false`; its negation was rewritten as `notEqual('1')` → kept as a negation.
- **A subclass with a predicate of its own inherited the axioms of the library class** (#63, BUG-20261013-IY5H). The universality of `AllEntitiesSpecification`, the rules of `isNull()`, `isNotNull()` and `in()` and the type bound were applied by `instanceof`, so a user subclass that redefines `isSatisfiedBy()` (an "active customers" over `AllEntitiesSpecification`) was treated as the library class. **Before → after**: `Spec::simplify(all(Customer) AND Active(Customer))` accepted an inactive customer → refuses it; `Active->isGeneralizationOf(all(Customer))` `true` → `false`. Such a subclass now gets the axioms shared by every specification only; the same for the wrapper of `a()`.
- **Type disjointness was read from specifications that are not bounded by their type** (#64, BUG-20261013-QTOR). **Before → after**: `unique(1, Customer)->isDisjointWith(all(Vip))` `true` → `false` (`Vip#1` satisfies both); `all(Customer)->isDisjointWith(not(all(Order)))` `true` → `false`, and `Spec::simplify(all(Customer)->and(not(all(Order))))` refused `Customer#1` → accepts it. Two types prove disjointness only when both sides are bounded by them.
- **Interval rules were applied to numeric strings** (#65, BUG-20261013-5FMU). PHP compares two numeric strings as numbers and other strings as text, and the subsumption and disjointness of bounds ordered them with `<=>`. **Before → after**: `Spec::simplify(Spec::greaterThan('9')->and(Spec::greaterThan('10')))->isSatisfiedBy('1a')` `true` → `false` (the tree answers `false`); `Spec::greaterThan('9')->isGeneralizationOf(Spec::greaterThan('10'))` `true` → `false`; `greaterThan('10')->isDisjointWith(lessThanOrEqualTo('1e1'))` `true` → `false`. Interval rules now apply only when neither bound is a numeric string.
- **`equals()` of the `Spec::a()` wrapper was asymmetric and ignored its annotation** (#66, BUG-20261013-CCH4). It compared the wrapped leaf only. **Before → after**: `a(greaterThan(5))->because('x')->equals(a(greaterThan(5)))` `true` → `false`; `a(greaterThan(5))->equals(greaterThan(5))` `true` → `false` (the reverse was already `false`). It is now structural and symmetric, annotations included, so `simplify()` merges two wrappers only when they report the same.
- **Integer bounds were closed without an integer type** (#67, BUG-20261013-ST36). The algebra took `x > 10` as `x >= 11`, but the relational leaves accept any number (`greaterThan(9)` accepts `9.5`) and the library has no integer-typed leaf. **Before → after**: `Spec::greaterThan(10)->isDisjointWith(Spec::lessThan(11))` `true` → `false` (`10.5` satisfies both); `Spec::isContradiction(Spec::greaterThan(10)->and(Spec::lessThan(11)))` `true` → `false`, and its simplification no longer refuses `10.5`; `Spec::greaterThanOrEqualTo(5)->isGeneralizationOf(Spec::greaterThan(4))` `true` → `false`. An opt-in integer mode that gives the closing back where it is sound is roadmap milestone 25.
- **`simplify()` traded an answer for an error by subsumption** (#71, BUG-20261013-T6CS; up to 2.0.0, found by the extended soundness bench). AND and OR evaluate left to right and stop at the first operand that decides, but the simplifier dropped a redundant operand even when it came first and decided alone, exposing a later operand that raises for that candidate. **Before → after:** `simplify(greaterThan(6) OR notEqual(1))->isSatisfiedBy(9.5)` raised `IncompatibleTypeException` → `true`; `simplify(lessThan(6) AND equalTo(1))` on `9.5` raised → `false`. A redundant operand that comes first is now dropped only when the operands it would expose raise only where it raised, read from the leaves' type guards; about 11–15% of the bench's node removals are given up for it.
- **`simplify()` evaluated operands the original never reached when it absorbed a chain** (#69, BUG-20261013-ZYEC). When a conjunction (disjunction) is proven a contradiction (tautology), the absorbing constant went after the kept annotated operands. **Before → after:** `simplify((isNull() AND equalTo(5)) AND at($d)->withCode('C1'))->isSatisfiedBy(true)` raised → `false`; the result is now `alwaysFalse() AND at($d)`: the constant takes the place of the first removed operand, so it decides before any later operand.

## [1.14.0] - 2026-10-11

The second round of follow-ups of the PDO repository (roadmap milestone 21c), all optional and additive (MINOR): `#[ManyToMany]` associations through a join table, a public way to declare the collection of an aggregate built by hand as loaded, `iterate()` with relations on MySQL unbuffered queries, and booleans stored as text (`CHAR(1)` `'Y'`/`'N'`). A mapping and a repository that use none of them behave as in 1.13, apart from the statements of a read with relations (see *Changed*). The release also fixes the text operators so that the database selects the rows the in-memory evaluation accepts, on every column collation (see *Fixed*): this changes results on MySQL, MariaDB and SQLite. No new Composer dependency.

### Added

- **`#[ManyToMany(target, joinTable, joinColumn, inverseJoinColumn)]`** (`Mapping\ManyToMany`) and **`EntityMapping::manyToMany(string $property, string $target, string $joinTable, string $joinColumn, string $inverseJoinColumn)`**, equal to the attribute (`equals()`, `describe()`); `RelationMapping::MANY_TO_MANY`, `isManyToMany()`, `isCollection()`, `$joinTable`, `$inverseJoinColumn`. The join table (optionally `schema.table`) and its two columns come only from the mapping and are validated as identifiers. An association, never a composition, and the target repository must use the same connection (`withRelated()` refuses another one):
  - **Eager loading** with `with('tags')`: per batch, `SELECT owner, target FROM join WHERE owner IN (...)`, then the targets by `IN` in their repository's read scope (two queries per batch; more only past the driver's parameter limit); a soft-removed target is left out of the collection and its link stays.
  - **Writes.** `put()`, `putAll()` and `insertAll()` of an owner whose collection was loaded (or that was just inserted) read its stored links once per batch, insert the links of the targets added (multi-row `INSERT`) and delete those of the targets that left the collection, only targets loaded with it (one `DELETE ... WHERE (owner = ? AND target = ?) OR ...` per chunk), never writing or deleting a target; a target without an identifier is refused before any write. A collection that was **not** loaded never touches the join table, even when it holds targets.
  - **Removal.** A hard removal of the owner (`forceRemove()`, `remove()` without `#[SoftDelete]`, `removeAll*()`) deletes its links first (one `DELETE ... WHERE owner IN (SELECT id FROM owner WHERE ...)` when `removeAll*()` stays one statement); a soft removal keeps them.
  - **`whereRelation('tags', $spec)`** goes through the join table: `id IN (SELECT owner FROM join WHERE target IN (SELECT id FROM target WHERE ...) AND owner IS NOT NULL)`, one statement; in memory the targets are read once, then their links (`InQuerySpecification` gains an optional `JoinTableHop`, built only by `whereRelation()`, and `getThrough()`).
- **`PdoRepository::markLoaded(object $entity, string ...$relations): void`** declares the collections (`#[OneToMany]` or `#[ManyToMany]`) of an entity built by hand as loaded and **whole**: the next `put()` removes, relative to what the collection holds then, the orphans of a composition or the links of an association it lacks (soft-removed targets aside). **Declaring an incomplete collection deletes what it lacks**, including a child or a link someone else added, which a collection loaded by `with()` never removes; after the write the collection is loaded as usual. **`markUnloaded(object $entity, string ...$relations): void`** makes a collection say nothing again (the next `put()` removes nothing and touches no link).
- **`BooleanStorage::Char`**: a Boolean column stored as text, `'Y'`/`'N'` unless declared otherwise, per column (`#[Column(booleanAs: BooleanStorage::Char, trueValue: 'S', falseValue: 'N')]`, `EntityMapping::column(..., trueValue:, falseValue:)`) or as the default of the mapping (`#[Table('t', booleanAs: BooleanStorage::Char, trueValue: ..., falseValue: ...)]`, `EntityMapping::booleanAs(BooleanStorage $storage, ?string $trueValue = null, ?string $falseValue = null)`, `getBooleanValues()`); `ColumnMapping::$trueValue`, `$falseValue`, `$booleanValuesDeclared`, `isCharBoolean()`. The texts are 1 to 16 letters or digits, different whatever the case; texts declared for a column that is not stored as `Char` are refused by `assertComplete()` (and so by the repository). Writes store the declared text; reads accept the two texts in any case (without the spaces a `CHAR` column pads with) and `NULL` as `null`, and **any other stored value throws `Exceptions\DataIntegrityException`** (`getColumn()`, `getProperty()`, `getStoredValue()`; an `InvalidArgumentException`, as the other conversion errors), never a silent `false`, in `find*()`, `iterate*()`, `select()`, `aggregate()` and `EntityMapping::hydrate()`. A comparison with a boolean compiles to every case form of the text, `"active" IN ('Y', 'y')` (`LOWER("answer") = 'false'` for a text of more than two letters), so the database finds exactly the rows a read accepts; the null semantics of 1.11.0 hold.
- **`SqlQueryVisitor::formatBooleanComparison(string $column, bool $value): ?string`**, a protected hook: a subclass may answer a boolean comparison with a whole condition (the repository does for `BooleanStorage::Char`); the base visitor answers null and keeps its literal.

### Changed

- **A read with relations finishes its own query before loading them.** `iterate*()` of a `with()` view pages by key, `WHERE ... AND id > :ks_after ORDER BY id LIMIT <batch + 1>`: each page is fetched whole and its cursor closed before the relations of its entities load, then yielded, so it works on MySQL unbuffered queries and holds one page at a time; `find*()` and `findPage()` read all their rows before loading the relations, by batches of `withBatchSize()`. The entities, the relations loaded and their order are unchanged; the statements differ (a logger counts one page query per batch for `iterate()`, where 1.13 ran one query). Without relations `iterate()` still streams one cursor.

### Fixed

Text operators now select in the database the rows the in-memory evaluation of the same specification accepts. Checked on SQLite, PostgreSQL 17, MySQL 8.4 and MariaDB 11.4, column by column (MySQL/MariaDB: `utf8mb4_unicode_ci`, the server default, `utf8mb4_bin`, `latin1_swedish_ci`, `latin1_bin`, with emulated and native prepares; PostgreSQL: the default and `"C"`; SQLite: `BINARY` and `NOCASE`).

- **MySQL and MariaDB, `regex()`.** Before: the case-sensitive form `col REGEXP BINARY :p` failed with error 3995 on MySQL 8 on every collation, and on MariaDB compared bytes (`^caf.$` missed `café`); the case-insensitive form `col REGEXP :p` was case-sensitive on `_bin` columns. After: the case rule travels in the pattern as an inline flag, `col REGEXP CONCAT('(?-i)', :p)` or `CONCAT('(?i)', :p)`, which both regex engines honour over any collation.
- **MySQL and MariaDB, `LIKE`** (`startsWith`, `endsWith`, `contains`, the wildcards, `equalIgnoreCase`). Before: the case-sensitive form `BINARY col LIKE :p` compared bytes, so `_` missed a multibyte character; the case-insensitive form `col LIKE :p` was case-sensitive on `_bin` columns and ignored accents on `_ai` ones (`contains('jose', false)` matched `José`, which memory does not). After: `CONVERT(col USING utf8mb4) COLLATE utf8mb4_bin LIKE :p`, and `LOWER(CONVERT(col USING utf8mb4)) COLLATE utf8mb4_bin LIKE LOWER(:p)` for the case-insensitive form. Neither form uses an index on the column.
- **SQLite, case-sensitive `LIKE`.** Before: SQLite's `LIKE` ignores the case of ASCII letters, so `startsWith('Caf')` also matched `café`, `CAFÉ` and `cafe`. After: the case-sensitive form is `col GLOB :p`, with the pattern converted to GLOB syntax (`*`, `?` and `[` in the text become one-character classes).
- **`equalIgnoreCase()` in every dialect and in the `TCriteria` bridge.** Before: the value went to `LIKE` unescaped, so `equalIgnoreCase('a_b')` also matched `axb` and `equalIgnoreCase('50%')` matched `500`. After: `%`, `_` and the escape character are escaped (`ESCAPE '!'`).
- **In memory, case-insensitive `startsWith()`/`endsWith()`/`contains()`.** Before: the regex carried `i` without `u`, so only ASCII letters were folded and `endsWith('É', false)` rejected `café`, while `equalIgnoreCase()` and the wildcard matcher already folded Unicode since 1.5.0. After: the modifier is `iu` when the literal is valid UTF-8.
- **What changes for an existing query:** a query that relied on the old behaviour returns other rows: accent-insensitive matches through `LIKE` on MySQL `_ai` columns and ASCII case-insensitive matches of a case-sensitive operator on SQLite disappear, and case-insensitive operators on `_bin` columns now ignore case. The rows returned are the ones the in-memory evaluation returns.

### Notes

- **`iterate()` with relations is not one snapshot**: its pages are separate statements, so a row written by someone else during the iteration may or may not be seen, as with any keyset pagination (run it inside a transaction with a suitable isolation level when that matters). Measured with 10 000 rows and `with('tags')` in pages of 500: about 1 MB of peak memory, the same as for 2 000 rows, against about 20 MB for `find()`.
- **An association writes only links**: changing a target held in a loaded collection writes nothing to the target (put it through its own repository), and link changes do not change the owner's row, so a `TriggeringRepository` over the owner sees no crossing from them.
- **`markLoaded()` trusts the caller**: use it only for a collection known to be complete; a collection loaded by `with()` stays the safe path.
- **Char comparisons are literals**, not parameters: the texts come only from the mapping and are restricted to letters and digits.
- Checked against PostgreSQL 17 and MySQL 8.4 (`iterate()` with relations also on a connection with `PDO::MYSQL_ATTR_USE_BUFFERED_QUERY = false`) as well as SQLite.
- **Case folding of non-ASCII letters follows the database where it folds ASCII only**: SQLite and PostgreSQL columns with the `"C"` collation (a case-insensitive `'É'` does not match `'é'` there). Plain `=` (`equals()`) remains the database's own comparison, so MySQL `_ci` collations ignore case and accents there; declare the column `utf8mb4_bin` for exact equality. Write a regex with `u` when it matches non-ASCII text: in memory, `.` without `u` is one byte.

## [1.13.0] - 2026-10-11

The follow-ups of the PDO repository (roadmap milestone 21b), in three parts, all optional and additive (MINOR): the bookkeeping around a table (SQL log, booleans stored as integers, default time zones, creation and modification timestamps, soft delete, repository hooks, batch insert), set-based operations (bulk update by specification, projections, grouped aggregates, subqueries over another repository) and relationships (`#[ManyToOne]`, `#[OneToMany]`, eager loading in batch, compositions with safe orphan removal). One fix: combining two SQL clauses no longer loses or misbinds a parameter. A mapping and a repository that use none of the new options behave as in 1.12 (the 1.11 test battery of the repository runs unchanged), apart from the existence check of `putAll()` (see *Changed*). No new Composer dependency.

### Added

#### Lifecycle, types and batch insert

- **SQL log.** `Persistence\IQueryLogger::log(string $sql, int $parameterCount, float $milliseconds, ?array $parameters)` receives every statement of a repository after it ran or failed (`$milliseconds` covers prepare, bind and execute). `PdoRepository::withQueryLogger(?IQueryLogger $logger, bool $logParameters = false)`, `getQueryLogger()`, `logsParameterValues()`: the parameter **values are not logged by default**, since they can be personal data; `$parameters` is null unless `logParameters: true`. An exception thrown by a logger is ignored. `InMemoryQueryLogger(int $capacity = 10000)` keeps the latest entries (`entries()`, `statements()`, `clear()`).
- **Booleans stored as integers.** `Mapping\BooleanStorage` (`Native`, the default, and `Integer`), per column (`#[Column(booleanAs: BooleanStorage::Integer)]`, `EntityMapping::column(..., booleanAs:)`) or as the default of a mapping (`#[Table('t', booleanAs: ...)]`, `EntityMapping::booleanAs()`); the column wins. `Integer` writes 1/0 on every driver, PostgreSQL included, binds 1/0 in specifications and compiles boolean literals as `col = 1` / `col = 0`; reading accepts both forms whatever the storage.
- **Default time zones.** `#[Table('t', timezone: 'America/Sao_Paulo')]` / `EntityMapping::timezone()` for the temporal columns of a mapping and `PdoRepository::withTimezone(?string)` / `getTimezone()` for those of a repository, for tables that hold local time without an offset. Precedence: the column's zone, then the mapping's, then the repository's, then UTC. `getMapping()` returns the mapping with the repository's zone applied.
- **Timestamps.** `#[CreatedAt]` and `#[UpdatedAt]` (on a property, or on the class with `property:`; builder `createdAt()`/`updatedAt()`): the creation time is filled by the `INSERT` when the entity holds none (a value already there, as in an import, is kept) and never updated; the modification time is set by the `INSERT`, every `UPDATE` and the soft removal. The instant comes from `PdoRepository::withClock(?Closure $clock)` (the system clock by default), read once per call and truncated to the second; a `Date` column gets the date at midnight in its zone.
- **Soft delete.** `#[SoftDelete('deleted_at')]` on the class (with an optional `property:`) or `#[SoftDelete]` on a nullable date property; builder `softDelete(string $column = 'deleted_at', ?string $property = null)`. `remove()` and `removeAll*()` write the instant into the column instead of deleting, touching only live rows and incrementing the `#[Version]` counter like any write. Every read (`find*()`, `iterate*()`, `count*()`, `findSingle()`, `findPage()`, `findById()`, `contains()`, and the new `select()`, `aggregate()` and subqueries) leaves the marked rows out; `withTrashed()` and `onlyTrashed()` return views that also see, or only see, them (`seesTrashed()`); `forceRemove(IEntity $entity): bool` deletes for real. `put()` of an entity whose row is marked behaves as after a physical delete: a versioned copy throws `OptimisticLockException`, an unversioned one is written back and visible again. `toWhereClause()` does not include the soft delete condition. `EntityMapping::getSoftDelete()`, `hasSoftDelete()`, `getCreatedAt()`, `getUpdatedAt()`.
- **Repository hooks.** `beforePut()`, `afterPut()`, `beforeRemove()`, `afterRemove()` take callables `fn(IEntity $entity, PdoRepository $repository): void`, run inside the write's transaction: an exception in any of them rolls the write back and propagates. `beforePut` runs before the identifier is generated and the timestamps are set; `afterRemove` runs only when a row was removed. With remove hooks (or a cascaded collection) `removeAll*()` loads the matching entities and removes them by identifier, so a hook is never bypassed; without them it stays one statement. The entity class gains nothing.
- **`EntityMapping::extract(object $entity): array`** (column => property value, without the database) and **`hydrate(array $row): IEntity`** (an entity built from a row without calling its constructor, each value converted like a fetched one): the `toArray()`/`fromArray()` of an active record.
- **`PdoRepository::insertAll(array $entities): int`** inserts new entities with multi-row `INSERT`s, without the existence `SELECT` of `put()`, in one transaction; a row that already exists (a soft-removed one included) fails on its key and nothing of the call is kept. `withBatchSize(int $rows)` / `getBatchSize()` (`DEFAULT_BATCH_SIZE = 1000`); a statement never holds more parameters than the driver accepts (PostgreSQL and MySQL 65 535, SQLite 32 766 from 3.32 and 999 before, SQL Server 2 000 and 1 000 rows, 999 elsewhere). Identifiers generated in PHP go in the batch; Oracle, Firebird, Informix and ANSI insert one row per statement.

#### Set-based operations

- **`PdoRepository::updateWhere(ISpecification $specification, array $values): int`**: one `UPDATE ... SET ... WHERE <compiled specification>` over the matching live rows, in a transaction, loading no entity. Values are converted by the type of their column; the identifier, the version counter, the lifecycle columns, unmapped properties and values of the wrong type are refused before any SQL. `#[UpdatedAt]` is stamped and `#[Version]` incremented (`COALESCE(version, 0) + 1`), so a copy loaded before becomes stale. With the in-memory fallback on, a specification that cannot be translated loads the matching entities and updates their rows by identifier.
- **`PdoRepository::select(ISpecification $specification, array $properties): iterable`**: a generator of arrays keyed by property name, ordered by the identifier, each value converted like a read value, without building entities; only readable mapped properties can be selected.
- **`PdoRepository::aggregate(ISpecification $specification): PdoAggregateQuery`**, immutable: `groupBy(string ...$properties)`, `count(?string $property = null, ?string $alias = null)`, `sum()`, `avg()`, `min()`, `max()` and `get(): list<array>`. Keys: the group properties, then `count`, `count_<prop>`, `sum_<prop>`, ... or the aliases given. Groups are ordered by their keys with the `NULL` group first. `sum`/`avg` take Integer, Float and Decimal columns, `min`/`max` any column but Boolean and Json, `groupBy()` any column but Json.
- **`Spec::inQuery(string $property, PdoRepository $other, ISpecification $where, string $otherProperty)`** (`Repositories\Pdo\InQuerySpecification`): inside a query of a `PdoRepository` on the same connection and dialect it compiles to `col IN (SELECT othercol FROM other WHERE ... AND othercol IS NOT NULL)`, with the read scope of `$other` and the parameters of both queries renamed apart; elsewhere it cannot be translated (or is evaluated in PHP with the in-memory fallback). In memory the subquery runs once per instance of the leaf (through `select()` of `$other`) and its values are kept; membership compares date-times by instant, enums by value, integers and integral floats as one number. `PdoRepository::toSubquery(ISpecification $specification, string $property, string $parameterPrefix = 'q')` returns the subquery.
- **`SqlQueryVisitor`** gains two protected hooks for subclasses: `formatBooleanLiteral(bool $value)` (the repository answers per column for `BooleanStorage::Integer`) and `translateExtensionLeaf(ISpecification $specification, string $column)` (the repository translates `Spec::inQuery()` with it; the base visitor refuses that leaf as before).

#### Relationships

- **`#[ManyToOne(target, joinColumn)]`**, a reference (aggregation): the foreign key column must also be mapped to a scalar property, which stays the stored truth. **`#[OneToMany(target, mappedBy, cascade: false)]`**, a collection whose `mappedBy` is the child's foreign key property or its `#[ManyToOne]` back reference; `cascade: true` makes it a composition. Builder: `EntityMapping::manyToOne(string $property, string $target, string $joinColumn)` and `oneToMany(string $property, string $target, string $mappedBy, bool $cascade = false)`, equal to the attributes (`equals()`, `describe()`); `getRelations()`, `getRelation()`, `getJoinColumn()`, `isRelationLoaded()`; `Mapping\RelationMapping`. A relation property is not a column: it is not in `getColumns()` or `extract()`, and a specification cannot read it.
- **`PdoRepository::withRelated(IRepository ...$repositories)`** registers the repositories of the related classes: a `PdoRepository`, or a decorator that exposes `getInner()` (`TriggeringRepository`), read through its `PdoRepository` and written through the decorator.
- **Eager loading in batch.** `with(string ...$paths)` returns a view (`getEagerRelations()`) whose reads (`find*()`, `iterate*()`, `findSingle()`, `findPage()`, `findById()`) load the given relations, dotted paths included (`with('items', 'items.product', 'customer')`), with one `SELECT ... WHERE fk IN (...)` per relation and batch of `withBatchSize()` entities (more only past the driver's parameter limit), in the read scope of the related repository; the entities of a batch that reference the same row share one instance. There is no lazy loading and no proxy. `isLoaded(IEntity $entity, string $relation)`: a relation that was not loaded keeps its default (`[]`, `null`) and the repository knows it (the state lives outside the entity).
- **Writes.** A reference is never cascaded: `put()` writes the identifier of the referenced object into the foreign key property (an object without one is refused), and a `null` reference clears the key only when it was loaded non-null. A composition is written after its parent in the parent's transaction (same connection required), with the foreign key and the back reference set, by `put()`, `putAll()` and `insertAll()`. Orphans are removed only when the collection was loaded (or the parent was just inserted), and only the children loaded with it that still belong to it, each with its version checked; a collection that was not loaded is never taken as empty. Moving a child between two loaded parents is safe within one `putAll()`. Removing a parent removes its children first: a soft-deleting parent marks the children that have `#[SoftDelete]` and keeps the others, a hard delete (`forceRemove()`, or a parent without soft delete) deletes every child row.
- **`whereRelation(string $relation, ISpecification $where)`**: the filter through a relationship as a `Spec::inQuery()` on the foreign key, `customer_id IN (SELECT id FROM customer WHERE ...)` for a reference, `id IN (SELECT order_id FROM item WHERE ...)` for a collection.

### Changed

- **`PdoRepository::putAll()` reads the existence of the rows with one `SELECT ... IN` per batch** of `withBatchSize()` entities instead of one `SELECT` per entity. The rows written, the transaction (all or nothing) and the exceptions are unchanged; the statements a logger or a recording connection sees are fewer.

### Fixed

- **Combining two SQL clauses no longer loses or misbinds a parameter.** `SqlWhereClause::and()` and `or()` merged the parameters of both clauses with `array_merge()`: the same name bound to two values kept the second in silence, and a clause with positional (`?`) parameters combined with one with named (`:name`) parameters produced a statement a driver may bind wrongly without an error (SQLite does). **Before → after**: `(new SqlWhereClause('"a" = :p1', ['p1' => 1]))->and(new SqlWhereClause('"c" = :p1', ['p1' => 3]))` returned the parameters `['p1' => 3]` (the `"a"` condition compared with 3) → throws `LogicException`; `(new SqlWhereClause('"a" = :p1', ['p1' => 1]))->and(new SqlWhereClause('"b" = ?', [2]))` returned `['p1' => 1, 0 => 2]` → throws `LogicException`. The same name with the same value is kept once, and positional parameters are appended in order, as before. Code that combines clauses compiled separately is the one affected. Affects every version up to 1.12.0.

### Notes

- **MySQL**: `updateWhere()` returns the rows whose values changed unless the connection sets `PDO::MYSQL_ATTR_FOUND_ROWS` (with `#[UpdatedAt]` or `#[Version]` every matched row changes), and MySQL refuses a subquery (`Spec::inQuery()`, `whereRelation()`) on the table being updated.
- **`auto` identifiers in batch** come back by `RETURNING` on PostgreSQL (assigned in ascending order); on the other drivers the rows that need a database-generated identifier are inserted one by one, since MySQL does not guarantee consecutive values for a multi-row `INSERT` (`innodb_autoinc_lock_mode = 2`, its default). Measured with 10 000 entities, `insertAll()` was about 3 times faster than `put()` row by row in SQLite and 20 to 40 times in PostgreSQL and MySQL; `updateWhere()` over 10 000 rows is one statement of a few milliseconds against about half a second loading and writing each entity.
- **Aggregates follow SQL's null rules**: `sum`/`avg`/`min`/`max` ignore `NULL` and give `null` over a group without values (the sum of nothing is `null`, not 0); `count()` counts rows and `count('prop')` non-null values; without `groupBy()` there is always one row. A `Decimal` column comes back as canonical decimal text (`'12.5'`, not `'12.50'`); SQLite has no decimal arithmetic and computes in floating point, rounded to 15 significant digits. An aggregate needs a translatable specification even with the in-memory fallback.
- **`updateWhere()` runs no per-entity hook** (`beforePut`/`afterPut`), and the domain event decorator (`TriggeringRepository`) does not see it: a `TriggerSweeper` notices the changes. Use `putAll()` when hooks or triggers must run.
- **Soft delete and relationships**: a soft-deleting parent keeps the children that have no soft delete (its row stays, so a revival finds them); a hard delete removes every child row, marked or not, since no child row may outlive its parent's. Children written through a `TriggeringRepository` publish their entries and exits, a bare `PdoRepository` publishes nothing; a `TriggeringRepository` over the parent reads its "before" without relations, so its triggers should read columns.
- **Timestamps are truncated to the second** (what every timestamp column stores), on the entity too.
- **`iterate()` with relations on MySQL unbuffered queries is not supported**: the relation queries run while its cursor is open. Use `find()`, or give the related repositories their own connection.
- **Not in this release** (roadmap milestone 21c): `#[ManyToMany]` (map the association entity with two references), a public way to mark the collection of an aggregate built by hand as loaded, the case above, and other storage forms of legacy booleans (`CHAR(1)`). Joins, DDL generation, a second-level cache and partitions stay out.
- Checked against PostgreSQL 17 and MySQL 8.4 as well as SQLite, and on PHP 8.2.

## [1.12.0] - 2026-10-11

One addition (MINOR, additive): domain events triggered by the passage of time (roadmap milestone 19b). A specification such as "unpaid and due more than 30 days ago" turns true while nobody writes the entity; a time-based trigger, a persisted state of every trigger for every entity and a sweeper run by a cron now publish those crossings through the same publishers and outboxes as the write path, and the 1.11 repository decorator keeps the same state, so a write and a sweep never publish one crossing twice. Code that does not use the new types behaves as in 1.11. No new Composer dependency.

### Added

- **Time-based triggers.** `SpecificationTrigger::timed(string $name, Closure $specificationAt, ?string $onEnter = null, ?string $onExit = null, ?Closure $crossedAt = null)`: the specification is built by `$specificationAt(DateTimeImmutable $now)` at every evaluation, with the instant of the write or of the sweep; the factory receives the instant and never reads a clock. `isTimed()`, `specificationAt(DateTimeImmutable $now)` (the fixed specification for a plain trigger), `hasCrossingInstant()` and `crossingInstant(object $entity, DateTimeImmutable $now, DomainEventKind $kind)`. The public `$specification` of a time-based trigger is a placeholder that throws `LogicException` when evaluated without an instant. `TriggerSet::timedTriggers()` and `hasTimed()`.
- **`TriggerEvaluator`** builds the specification of a time-based trigger with the instant it receives: `statesOf(TriggerSet, ?object, ?DateTimeImmutable $now = null)` (new optional parameter) and `satisfies(SpecificationTrigger, object, ?DateTimeImmutable $now = null)`; `changes()` uses its `$now`, or the evaluator's clock when it has one. Without an instant a time-based trigger is an evaluation error of that trigger, never a silent "not satisfied".
- **Trigger state** (`Antevemus\ASpecification\DomainEvents\State`): `ITriggerStateStore` keeps one `TriggerState` (trigger, entity class, entity id, `satisfied`, `evaluatedAt` in UTC, `version`) per trigger and entity: `find()`, `findByEntity()`, `findMany()`, `findSatisfied(string $triggerName, string $entityClass, int $limit, ?string $afterEntityId = null)` (keyset pages in entity id order), `count()`, and compare-and-set writes on the version read: `compareAndSet(..., ?int $expectedVersion, bool $satisfied, DateTimeImmutable $evaluatedAt): bool` (a null version inserts and fails when the row exists) and `compareAndDelete(..., int $expectedVersion): bool`. A lost write returns false and changes nothing. Implementations: `InMemoryTriggerStateStore` (takes part in an `InMemoryTransactionManager`) and `PdoTriggerStateStore(PDO $pdo, string $table = 'domain_event_trigger_state', string $schema = '')`: portable parameterized SQL, the compare-and-set as `UPDATE ... WHERE version = :expected`, the first record as a check then an `INSERT` that loses to the primary key when another writer inserted first (under a savepoint on PostgreSQL, so the caller's transaction survives), a locking re-read inside a transaction on MySQL (so that a writer that lost reads the committed row under REPEATABLE READ), failures as `DomainEventPersistenceException` with the SQLSTATE.
- **`TriggerSweeper`**`(IRepository $repository, string $entityClass, TriggerSet $triggers, ITriggerStateStore $states, IDomainEventPublisher $publisher, ?ITransactionManager $transactions = null, ?IDomainEventErrorReporter $errors = null, ?TriggerEvaluator $evaluator = null, ?Closure $identitiesSpecification = null, int $batchSize = 500)`:
  - `sweep(DateTimeImmutable $now, ?int $limit = null): SweepReport`, per time-based trigger: the states recorded as inside are read in pages and checked with one `COUNT(*)` of `spec(now) AND id IN (page)` per page, so entities still inside are never loaded; those that left (or were removed) are exits. When the entities confirmed inside are as many as the `COUNT(*)` of `spec(now)`, nothing can enter and no entity is loaded; otherwise the entities satisfying `spec(now)` are streamed and those not recorded inside (false or no state) are entries. Each crossing re-reads the entity, confirms it in PHP (the SQL only narrows), and runs in one transaction: the compare-and-set of the state on the version read during the scan (an exit of a removed entity deletes the state), then the publication of the event when it won. A lost compare-and-set publishes nothing. `$limit` bounds the crossings of one call.
  - `baseline(DateTimeImmutable $now): SweepReport` records the current state of every trigger (plain and time-based) for every entity and deletes the satisfied states of entities that no longer exist, publishing nothing.
  - An event is stamped with `$now`, or with the trigger's `crossedAt` instant when it lies after the evaluation recorded in the state and not after `$now`: the same crossing then has the same idempotency key in every sweep and every process, and a re-entry after an exit still gets its own.
  - Errors (a factory or a calculator that throws, an entity whose id cannot be read, an entity of another concrete class than the sweeper's) are reported with the new `TriggerEvaluationError::SIDE_SWEEP` and never stop the other triggers; failures of the repository, the store or the publisher propagate.
  - `TriggerSweeper::byIdPropertyIn(string $property = 'entityId', ?Closure $cast = null)` builds the identities specification for a repository that translates specifications to SQL; over a `PdoRepository` it is the default (integer identifiers compared as integers).
- **`SweepReport`**: `enteredCount()`, `exitedCount()`, `recordedCount()`, `conflictCount()`, `getEvents()`, `eventNames()`, `getErrors()`, `hasErrors()`, `entitiesLoaded()`, `statesRead()`, `limitReached()`, `toArray()`.
- **`TriggeringRepository`** takes an optional state store (new last constructor parameter `?ITriggerStateStore $states = null`, `getStates()`): the "before" of each trigger is the recorded state when there is one (the identity lookup runs only when a trigger of the entity has none); every write records the state of every trigger by compare-and-set, reading the row again and deciding on its new value when another writer or a sweeper changed it (at most `TriggeringRepository::MAX_STATE_ATTEMPTS` times, then `DomainEventPersistenceException`); `remove()` and `removeBy()` delete the states of the removed entities. Without a store, the behaviour of 1.11 is unchanged.
- **`resources/sql/domain_events.ansi.sql`**: the `domain_event_trigger_state` table, `CREATE TABLE IF NOT EXISTS`, primary key `(trigger_name, entity_class, entity_id)`, `satisfied` as `SMALLINT` with a `CHECK (satisfied IN (0, 1))`, `version` with a `CHECK (version >= 1)`, lookup indexes declared as `UNIQUE` constraints. Running the script again on a 1.11 database adds the table and leaves the outbox untouched.

### Changed

- **`PdoRepository` frees the SQL compiler of each query when the query returns.** The compiler kept a closure bound to itself, so every query left a reference cycle for PHP's cycle collector: memory grew with the number of queries until the collector ran (about 36 KB per query with a 500-value `IN` list, so about 360 KB per sweep of 10 000 rows). Queries, parameters and results are unchanged.

### Notes

- **Introducing a trigger over existing data: run `baseline()` first.** An entity without a recorded state counts as "not satisfied", so the first sweep publishes an enter for every entity already inside. That is the truth, but rarely what a mailing wants.
- **Cost and memory**, measured with `PdoRepository` on SQLite: over 10 000 invoices, 5 000 of them inside, a sweep that finds no crossing loads no entity and runs 22 statements; a sweep with 100 crossings loads the 5 100 candidates of the query plus one re-read per crossing; the memory peak (one page of 500 states) is the same as over 1 000 invoices. A write through `TriggeringRepository` with a store costs one read of the entity's states and one compare-and-set per trigger.
- **Concurrency**: two sweepers, or a sweeper and a write, are correct together (one transaction and one compare-and-set per crossing, the outbox's unique idempotency key as the second barrier), not faster: the work is not partitioned between processes. There is no embedded scheduler. Under REPEATABLE READ or SERIALIZABLE on PostgreSQL, a race may surface as a serialization failure (the work is rolled back and can be retried) instead of a lost compare-and-set; it never publishes twice. Checked against PostgreSQL 17 and MySQL 8.4 as well as SQLite.
- **One sweeper per concrete entity class**: the states are keyed by it, and an entity of another class found in the repository is reported, never recorded. On MySQL with unbuffered queries, give the sweeper a repository on its own connection: it reads states while the entity cursor is open. The keyset pages follow the collation of `entity_id`: on MySQL declare it with a binary collation when two ids may differ only by case or accents.
- **Plain triggers are not swept** (they only change on writes); `baseline()` records them too, which gives `TriggeringRepository` a "before" for in-memory entities stored before the decorator existed.

- **`Antevemus\ASpecification\Repositories\Pdo\PdoRepository`**, an `IRepository` over one table (it extends `AbstractRepository`). `PdoRepository::forEntity(PDO $pdo, string $entityClass, ?ITransactionManager $transactions = null, $dialect = null)` reads the mapping from attributes; `new PdoRepository(PDO $pdo, EntityMapping $mapping, ?ITransactionManager $transactions = null, $dialect = null, ?ISynchronizer $synchronizer = null)` takes an explicit one. The dialect is deduced from the PDO driver when not given; the error mode of the connection is left untouched and driver errors surface as `PdoRepositoryException` (with the SQLSTATE).
  - **Queries**: the specification is compiled to a parameterized `WHERE` by the `SqlQueryVisitor`, with property names turned into the mapped columns. A property can be queried only when it is mapped **and** readable by name under the rule the in-memory evaluation applies (public, a public getter or `#[Specifiable]`); `entityId` always means the identifier column. A specification that cannot be translated throws `NonTranslatableSpecificationException` (or `UnsupportedSqlOperationException`): nothing is filtered in memory unless `withInMemoryFallback()` was called, which reads the whole table and evaluates the specification in PHP. `toWhereClause()` returns the clause a specification compiles to.
  - **Reads**: `find*()` and `iterate*()` (a generator over the cursor: one row and one entity at a time) order by the identifier; `count*()` is `SELECT COUNT(*)` and builds no entity; `findSingle()` asks for at most two rows in one query and throws when there is more than one; `findPage(ISpecification, int $limit, int $offset = 0, array $orderBy = [])` paginates through the dialect, with the identifier appended to the order so that pages never overlap; `findById()`; `contains()` by identity. Only the mapped columns are selected. Entities are built without calling their constructor; an `AbstractEntity` whose creation time is not mapped gets the hydration time.
  - **Writes**, each in a transaction of the `ITransactionManager` (by default a `PdoTransactionManager` on the same connection, which joins a transaction already open): `put()`/`update()` insert when the entity has no identifier or its row does not exist and update otherwise; `putAll()` writes every entity in one transaction (all or nothing); `updateWithDelta()` applies the delta, then updates; `remove()` deletes by identifier; `removeAll*()`/`removeBy()` is one compiled `DELETE ... WHERE` (identifiers deleted in chunks of 500 with the in-memory fallback).
  - **Optimistic locking** with a `#[Version]` counter: the `INSERT` writes 1, every `UPDATE` increments it and only matches the version the entity carries; a stale update or removal throws `OptimisticLockException` (`getEntityClass()`, `getEntityId()`, `getExpectedVersion()`, `getActualVersion()`) and writes nothing; a versioned copy whose row is gone is never re-inserted.
  - Partitions are not supported: `isNativelyPartitioned()` is false and `makePartition()` throws `PartitioningNotSupportedException` (a `PartitionCreationException`).
- **Mapping** (`Repositories\Pdo\Mapping`): the attributes `#[Table('schema.table')]`, `#[Column(name, type, property, enumClass, timezone)]`, `#[Id(strategy, column, type, sequence, property)]` and `#[Version(column, property)]` (on the property, or on the class with `property:` for a property a parent declares, such as `AbstractUlidEntity::$entityId` or `AbstractEntity::$version`), and the immutable builder `EntityMapping::for(Entity::class)->table()->id()->column()->version()`, which produces the same mapping (`equals()`, `describe()`). Table and column names must be plain SQL identifiers and are quoted by the dialect; a mapped property is read and written by reflection even when it is private, protected or readonly. `ColumnType`: `Auto` (inferred from the declared type), `String`, `Integer`, `Float`, `Decimal` (kept as text, never a float), `Boolean` (`TRUE`/`FALSE` in PostgreSQL, 1/0 elsewhere), `Date`, `DateTime` (`DateTimeImmutable` or `DateTime`, in the column time zone, UTC by default, with microseconds when present), `Json`, `Enum` (backed by value, pure by case name), `Raw`. `IdStrategy`: `Auto` (identity, serial or auto-increment; `INSERT ... RETURNING` in PostgreSQL, or `lastInsertId()` of the declared sequence), `Ulid`, `Uuid7`, `Assigned` and `Max` (`SELECT COALESCE(MAX(id), 0) + 1` inside the write transaction, compatible with the `IDPOLICY = 'max'` of Adianti's `TRecord`). Invalid declarations throw `EntityMappingException`.
- **Shared transaction port** (`Antevemus\ASpecification\Persistence`): `ITransactionManager` (`transactional(Closure $work): mixed`) and `PdoTransactionManager` (`getConnection()`, `inTransaction()`; a nested call joins the open transaction and the outermost owner commits or rolls back). The state machine's `StateMachine\Persistence\ITransactionManager` now extends the shared interface and its `Pdo\PdoTransactionManager` extends the shared class, without adding anything: code written against them compiles and behaves as before, and one instance can give the repository, the domain event outbox and the machine stores the same transaction.
- **Domain events from specifications** (`Antevemus\ASpecification\DomainEvents`):
  - `SpecificationTrigger(string $name, ISpecification $specification, ?string $onEnter = null, ?string $onExit = null)` (at least one event) and `TriggerSet` (immutable, ordered, unique names, `with()`).
  - `TriggerEvaluator::changes(TriggerSet, ?object $before, ?object $after, ?DateTimeImmutable $now)`: not satisfied → satisfied is an enter, the reverse an exit, no change nothing; a creation (`$before` null) that already satisfies is an enter and a removal (`$after` null) of an entity that satisfied is an exit. It returns `TriggerChanges` (iterable and countable over the events, with `getErrors()`): a specification that throws makes its trigger emit nothing for that write and adds a `TriggerEvaluationError` keeping the exception for the log; the other triggers are still evaluated. "Now" is injected, never read inside.
  - `DomainEvent` (immutable): name, trigger, kind (`DomainEventKind::ENTER`/`EXIT`), entity class and id, `occurredAt`, a payload with the trigger name and the entity id only, and a deterministic idempotency key (`de:` + SHA-256 of trigger, entity class, entity id, kind and instant).
  - Publishers behind `IDomainEventPublisher`: `InMemoryDomainEventPublisher` (tests and simple uses) and `OutboxDomainEventPublisher`, which writes each event as a pending entry of an `IDomainEventOutbox` (ULID event id = delivery order; an idempotency key already stored is skipped). Outboxes: `InMemoryDomainEventOutbox` and `PdoDomainEventOutbox` (table and optional schema validated as identifiers; portable SQL; failures reported as `DomainEventPersistenceException` with the SQLSTATE).
  - `DomainEventDispatcher(IDomainEventOutbox, DomainEventHandlerRegistry, ?int $maxAttempts = null, ?Closure $clock = null)::dispatchPending(int $limit = 100)`: delivers after the commit, in write order per entity, each handler receiving the event and its idempotency key; marks each entry delivered or failed (attempts + 1, last error message without stack trace, at most 2 000 characters); a failed entry holds its entity's later events back until it succeeds or, with `maxAttempts`, is exhausted; an event without a handler is a failed attempt. Delivery is at-least-once.
  - `TriggeringRepository`, a decorator of any `IRepository`: on `put()`/`putAll()`/`update()`/`updateWithDelta()` it reads the stored entity by its identity, writes, evaluates the triggers on the before and the after, and publishes; on `remove()`/`removeBy()` it publishes the exits of the removed entities; reads are delegated. Options: an `ITransactionManager` around each write, an `IDomainEventErrorReporter` (`NullDomainEventErrorReporter` by default), a clock, an identity specification (`byEntityId()`, a PHP predicate, by default; `byIdProperty('entityId')`, translatable to SQL, by default over a `PdoRepository`), and `failOnEvaluationError` (the write throws `DomainEventTriggerException` instead of going on). A failure of the publisher always propagates. `makePartition()` is refused, since a partition would take writes that bypass the triggers.
  - `MachineEventBridge(MachineRunner, array $eventTypes, Closure $instanceResolver, ?Closure $context = null, ?string $actor = null)`: a ready-made handler (`registerIn()`, `deliver()`) that sends a domain event to a state machine instance as an internal event with the domain event's instant, minimal payload and idempotency key, so a redelivery returns the original result from the runner's idempotency store; a rejected or unhandled machine event is a normal outcome, an unknown instance or a concurrency conflict propagates (the dispatcher retries).
- **`resources/sql/domain_events.ansi.sql`**: the `domain_event_outbox` table, portable SQL, `CREATE TABLE IF NOT EXISTS`, primary key on `event_id`, `UNIQUE` on the idempotency key, `CHECK` constraints on `kind`, `status` and `attempts`, lookup indexes declared as `UNIQUE` constraints (no `CREATE INDEX`), instants as fixed-width UTC text, the payload as `VARCHAR(4000)`.

### Fixed

- **`evaluate(null)` on a conjunction or disjunction agrees with `isSatisfiedBy(null)`.** A composite refuses a null candidate (`isSatisfiedBy(null)` is false, as in Domian), but `AndSpecification::evaluate(null)` and `OrSpecification::evaluate(null)` asked their operands and could answer satisfied — for example `Spec::isNull()->and(Spec::isNull())->evaluate(null)->isSatisfied` was `true`. **Before → after:** `true` → `false`, with one failure carrying the annotated message and code when there are any (otherwise "Null candidate is not permitted."), as `NotSpecification` already did. Affects every version up to 1.10.0.

- **`alwaysTrue()` and `alwaysFalse()` are translated by the SQL visitor.** The visitor only handled them in its composite branch, which they never reach (they are not composite specifications), so any tree that contained one could not be compiled. **Before → after**, with `Spec::toSql()` or a `SqlQueryVisitor`: `Spec::toSql(Spec::alwaysTrue())` threw `NonTranslatableSpecificationException` → `1 = 1`; `Spec::toSql(Spec::alwaysFalse())` → `1 = 0`; the same at any depth (`Spec::alwaysTrue()->and($spec)` → `(1 = 1 AND ...)`, `Spec::not(Spec::alwaysTrue())` → `NOT (1 = 1)`, as an operand of `nor`, inside a property clause), with the dialect's constant conditions. Affects every version up to 1.10.0.

- **Null values: the same specification gives the same answer in memory and in SQL (behaviour change).** In memory a property specification was not satisfied whenever the property value was `null`, without asking its inner specification, while the SQL visitor translated the inner specification over the column, where SQL's three-valued logic applies: `Spec::property('note', Spec::isNull())` was false in memory and `"note" IS NULL` (true) in SQL, and `NOT` over a comparison on a `NULL` column was true in memory and unknown in SQL (the row was left out). The in-memory evaluation is now the reference, with two-valued logic everywhere:
  - **In memory**, a null property value is handed to the inner specification; a property that cannot be resolved is still an evaluation error. A comparison (`greaterThan()`, `lessThan()`, `between()`, `equalTo('x')`, `notEqual('x')`, `in('a', 'b')`, `startsWith()`, `contains()`, `regex()`, ...) is false for `null`; `isNull()`, `equalTo(null)` and an `in()` holding `null` are true; an `and`/`or`/`not` written inside the property rejects the null value, as it rejects any null candidate (`Spec::property('x', Spec::notIn('a'))` stays false for `null`). **Before → after**, for `note = null` and `views = null`: `Spec::property('note', Spec::isNull())` false → **true**; `Spec::property('note', Spec::equalTo(null))` and `Spec::property('note', Spec::in('a', null))` false → **true**; `Spec::property('note', Spec::alwaysTrue())` false → **true**; `Spec::not(Spec::property('views', Spec::greaterThan(18)))` true → true (unchanged); `Spec::property('views', Spec::greaterThan(18))` false → false (unchanged). A null value that does not satisfy is still reported as the property's own failure (`Property 'x' is null on candidate object.`, or its `because()`/`withCode()`).
  - **In SQL** (`Spec::toSql()`, `SqlQueryVisitor`), every comparison on a column is guarded, `("age" IS NOT NULL AND "age" > :p1)`: false for a `NULL` column instead of unknown, so `NOT` and `NOR` over it give the in-memory answer. **Before → after**: `Spec::not(Spec::property('age', Spec::greaterThan(18)))` was `NOT ("age" > :p1)` and left out a row whose `age` is `NULL` → `NOT (("age" IS NOT NULL AND "age" > :p1))` includes it. An `and`/`or`/`not` directly inside a property is guarded as a whole (`Spec::property('status', Spec::notIn('A'))` → `("status" IS NOT NULL AND NOT ("status" IN (:p1)))`). `IS NULL`, `IS NOT NULL`, equality to `null` and an `IN` holding `null` are not guarded. The text of every generated comparison changes; the parameters, their names and the rows a positive filter returns do not. A subclass that knows a column never holds `NULL` can skip its guard through the new protected hook `SqlQueryVisitor::canBeNull(string $property)` (the `PdoRepository` does it for the identifier).
  - **In TCriteria** (`Spec::toCriteria()`, `TCriteriaBuilder`), a negated comparison accepts `NULL`. **Before → after**: `Spec::not(Spec::property('idade', Spec::greaterThan(18)))` `(idade <= 18)` → `(idade IS NULL OR idade <= 18)`; the same for the `<>`, `NOT LIKE`, `NOT IN` and `NOT REGEXP` a negation produces. A positive comparison is unchanged: a criteria has no `NOT`, so a filter that is unknown for `NULL` already leaves the row out. An `and`/`or`/`not` inside a property gets `col IS NOT NULL AND (...)` only when one of its filters matches `NULL` (`IS NULL`, `1 = 1`).
  - **ALinq**: the compiled predicate follows the same rules, and its `and`/`or`/`not`/`nor` now reject a null candidate, as the core does (the compiled `not` used to accept one).
  - **`PdoRepository`** (new in this release) takes the guards from the visitor; it no longer guards the whole property clause, which matched the old in-memory rule, so `Spec::property('note', Spec::isNull())` finds the rows whose `note` is `NULL`.
  - **`simplify()` and the algebra**: the inside of a property is not rewritten when the rewrite would change the answer for a null value (`property('x', alwaysTrue()->and(alwaysTrue()))` keeps its `and`, which rejects `null`), and the generalization, disjointness and contradiction of two property specifications take the null value into account.
  - **Who can be affected**: code that relied on "a null property is never satisfied", for example `property('x', isNull())`, `property('x', equalTo(null))`, `property('x', in('a', null))` or `property('x', alwaysTrue())` used as "x is set", and code or tests that compare the generated SQL text. "x is null" is now written `property('x', isNull())`; `not(property('x', isNotNull()))` keeps working. Affects every version up to 1.10.0.

### Notes

- **The database compares text its own way, and the in-memory evaluation does not follow it.** SQLite's `LIKE` ignores ASCII case by default, so `startsWith()`, `endsWith()`, `contains()` and the wildcard specifications can match more rows in SQLite than in memory. MySQL's default collations (`_ci`) ignore case (and, in the `_0900_ai_ci` family, accents) in `=` and `LIKE`: declare text columns with a binary collation (`utf8mb4_bin`) when the same specification must give the same rows in memory and in the database.
- **SQLite and `DECIMAL`**: a column declared `DECIMAL` has numeric affinity in SQLite and gives back `'59.90'` as `'59.9'`; declare it `TEXT` to keep the exact digits (comparisons on that column are then textual).
- **MySQL streaming**: `iterate()` streams only when the connection has `PDO::MYSQL_ATTR_USE_BUFFERED_QUERY` set to `false`; with the default buffered mode the driver holds the whole result before the first row (the repository leaves the connection's attributes untouched).
- **Known limitation of `TriggeringRepository` over the in-memory repositories.** They store the caller's object, so a mutation in place already changed the "stored" state; the decorator uses the trigger states it recorded at the last write of that object through it. An entity stored before the decorator existed (or written to the inner repository directly) and then mutated in place has no "before", and that write emits nothing. Repositories that hydrate a copy (`PdoRepository`) are not affected.
- **Domain events are evaluated on writes only.** A specification whose truth changes with time alone ("overdue for more than 30 days") crosses only when the entity is written through the decorator; a time-based sweeper is on the roadmap (milestone 19b). The payload carries the trigger name and the entity id, never the entity, so no personal data reaches a queue or a log.
- **Out of scope for the PDO repository in this version**: relationships and joins, DDL generation, second-level cache, partitions. `IdStrategy::Max` is subject to a race between concurrent writers (two transactions can read the same maximum; the primary key rejects the second `INSERT`): prefer `Auto`, `Ulid` or `Uuid7` for new tables.

## [1.10.0] - 2026-10-11

One addition (MINOR, additive): concurrent data resolution for I/O-bound specifications, the core part of roadmap milestone 15. A specification that depends on external data declares it instead of calling the service; a resolver fetches the data of the whole tree concurrently and then evaluates the tree, synchronously, as before. Code that does not use the new leaf behaves as in 1.9. No new Composer dependency: `ext-curl` is suggested, not required.

### Changed

- **`suggest` for `antevemus/alinq-collection`: `^1.4.2` → `^1.5.0`**, the latest ALinq release (the floor between the two packages follows the latest published version of the other).

### Added

- **`Antevemus\ASpecification\Resolution`**, a new namespace (directory `src/Resolution/`) with the whole feature, so that it can be read, and left out, as one unit.
- **`ExternalDataSpecification`** and **`Spec::external(string $source, array $parameters, ISpecification $specification)`**: "the data the source returns for these parameters satisfies the specification". Parameters are dot paths into the candidate (`['document' => 'customer.cpf']`, the `PropertyAccessor` notation); the inner specification is an ordinary one and decides, with its own `because()`/`withCode()`; an annotation on the leaf itself reports one failure with the inner failures as causes. A candidate that is not an object or an array, or a parameter whose path resolves to `null`, does not satisfy (no request is made); a missing path, an unknown source and any fetch failure are evaluation errors. `createRequest()` exposes the request a candidate produces; `isContradiction()` follows the inner specification.
- **`DataRequest`**: source name plus parameters already read from the candidate (strings, integers, finite floats, booleans; `Stringable` and `BackedEnum` converted). Its canonical key (`<source>#<sha-256 of the sorted parameters>`) is the same for the same data in any order, deduplicates fetches within a resolution and is the cache key; the hash keeps parameter values out of cache keys and logs.
- **Data sources**: `IDataSource` (`fetch()`, `getCost()`, `getTtl()`), `IHttpDataSource` (`createCall()`, `parseResponse()`), and two implementations:
  - `HttpDataSource`: fixed base URL, a path template with `{placeholders}` (in the path or in the query), method, headers (authentication included), optional body builder, its own time limit, cost and cache TTL; a 2xx response goes to `parse(int $status, array $headers, string $body)` (JSON decoded by default). Parameter values are percent-encoded (`.` included), so `/`, `?`, `#`, `..` or a whole URL cannot change the scheme, host, port or path, and the expanded URL is checked against the base URL before the call. Redirects are not followed and only `http`/`https` are allowed. `HttpCall` is the call it builds.
  - `CallableDataSource`: any synchronous callable receiving the parameters (a repository, an SDK, a gRPC client).
- **`DataSourceRegistry`**: sources by name (`register()`, `has()`, `get()`, `getNames()`); a name is registered once; `DataSourceRegistry::default()`/`setDefault()` is the registry the leaves use outside a resolver. Registering an `HttpDataSource` without `ext-curl` is refused.
- **`DataResolver`** (`new DataResolver(?DataSourceRegistry, ?IDataCache)`): `resolve(ISpecification, mixed $candidate, ?ResolutionPolicy): ResolvedData` collects the requests of the whole tree and fetches them; `evaluate(...)` resolves and evaluates. The HTTP calls of a stage run together in one `curl_multi`; callable sources run one after the other within the stage. `ResolvedData` holds each value, failure or skip by request (`isResolved()`, `get()`, `getError()`, `isSkipped()`, `getSkippedRequests()`, `getFailedRequests()`, `getFetchCount()`, `getStageCount()`, `getCacheHitCount()`) and evaluates inside its scope (`evaluate()`, `isSatisfiedBy()`, `run()`).
- **`ResolutionPolicy`** (`ResolutionMode`): `concurrent()`, the default, fetches every request in one stage and reports every failure, as an evaluation outside the resolver does; `tiered()`, an explicit choice when calls cost money, fetches by cost, cheapest first, and after each stage evaluates the tree in three-valued logic (satisfied, failed, unknown), skipping the remaining sources once the verdict can no longer change; `sequential()` fetches nothing beforehand and each leaf fetches when the evaluation reaches it. An optional `timeout` bounds the whole resolution (`ResolutionPolicy::tiered(timeout: 3.0)`, `withTimeout()`). A call is never started with less than 10 ms of that budget left (`CurlMultiTransport::MIN_START_BUDGET`): it ends as a time-limit failure without reaching the source, so no request (possibly a paid one) is spent on a call that cannot finish.
- **`ResolutionScope`**: the stack (reentrant, closed even when the code throws) through which the leaves read the resolved data. Outside every scope a leaf fetches its own data synchronously through the default registry: every specification keeps working without the resolver, only without concurrency.
- **Errors**: `DataResolutionException` (base), `DataFetchException` (`getSourceName()`, `getStatusCode()`: an HTTP status outside 2xx, a transport error, the time limit of the source or of the resolution, a parser or callable failure kept as previous exception) and `DataSourceNotFoundException`. A failed fetch is an evaluation error of its leaf with the 1.8.0 rule: failure with the generic message, `evaluation_error = true`, the exception in `$result->exception`; its message never carries the response body, the URL or a parameter value. No retry.
- **Cache between resolutions**: the `IDataCache` port (`has()`, `get()`, `set()`) and `InMemoryDataCache` (injectable clock). Only successful values of sources with a positive TTL are stored.
- **The SQL, TCriteria and ALinq visitors refuse the leaf** (negated or not, nested in a property restriction or not): `NonTranslatableSpecificationException`, `NonTranslatableCriteriaException` and the new `Linq\Exceptions\NonTranslatableLinqException` (an `InvalidArgumentException`; the ALinq visitor had no "non translatable" exception, and compiling the leaf would call the source once per item).
- **`composer.json`**: `ext-curl` in `suggest`.

### Notes

- **Same verdict, possibly fewer failures under `tiered()`.** For any tree, `isSatisfied` is the same under every policy and outside the resolver. A branch that `tiered()` did not fetch, because it could not change the verdict, reports no failure (it answers with the neutral outcome of its position), so its failures are the ones the other policies report minus those of the skipped branches; `isError` can also differ when a skipped source would have failed. `concurrent()`, `sequential()` and the evaluation outside a resolver report the same failures.
- **An `or` stops early only on its left operand.** In the core, an evaluation error on the left operand of an `or` aborts the disjunction (existing behaviour, unchanged), so an unknown left operand can never be skipped; an `and` with a false operand stops whatever its position.
- **A failed fetch never decides on its own**: it counts as unknown for the three-valued logic, so the next stage is still fetched.
- **`sequential()` does not skip operands of an `and`**: `evaluate()` evaluates both operands of a conjunction to report every failure (notification pattern), so every leaf it reaches fetches its data; it differs from the evaluation outside a resolver only by deduplication, cache and time limit.
- **Node types the resolver does not know** (anything but `and`, `or`, `not`, `nor`, property restrictions, the new leaf and ordinary leaves; subclasses included) are never guessed: they count as unknown until the data below them is fetched, and a leaf hidden inside a node that does not expose its operands is fetched when the evaluation reaches it.
- **Outside a resolver** there is no deduplication, no cache and no resolution time limit; the leaf uses `DataSourceRegistry::default()`, whatever registry a resolver was built with.
- **State machine guards stay pure**: a use case that needs external data resolves it before sending the event and passes it in the payload.

## [1.9.0] - 2026-10-11

Two additions (MINOR, additive): `simplify()`, which returns an equivalent, smaller specification (roadmap milestone 12), and state machine deadlines read from the context (a duration or an absolute instant) that can pause while a condition holds and resume with the balance kept. Code that does not use the new features behaves as in 1.8; the reference DDL gains one nullable column (see *Upgrading*). No new Composer dependency.

### Added

- **`simplify()`**: `SpecificationSimplifier::simplify(ISpecification): ISpecification`, with the shortcuts `AbstractSpecification::simplify()` and `Spec::simplify()`. It is not declared by `ISpecification`, so external implementations of the interface are unaffected.
  - Rules, applied bottom-up to a fixed point: identity (`A ∧ true = A`, `A ∨ false = A`), annihilation (`A ∧ false = false`, `A ∨ true = true`), double negation (`¬¬A = A`), idempotence (`A ∧ A = A`, `A ∨ A = A`, by `equals()`), flattening of nested `and`/`or` of the same kind, contradictory conjunctions → `alwaysFalse()` and tautological disjunctions → `alwaysTrue()` (the 1.6.0 structural detection), and subsumption (`A ∧ B = A`, `A ∨ B = B` when `A` is a special case of `B`, the 1.4.4 algebra). Not proven means not rewritten: there is no SAT solving.
  - Annotations are preserved: a node with `because()` or `withCode()` is simplified inside but never removed, merged into another node or replaced by a constant, unless the very same annotation is on both sides; an annotated `and`/`or` keeps at least two operands; a double negation over an annotated subtree is kept. The verdict and the annotated messages and codes reported by `evaluate()` do not change.
  - Immutable and idempotent: the input is never modified, unchanged subtrees are shared, simplifying a simplified tree returns that same tree, and the rewrite never adds nodes. AND, OR, NOT, NOR, property restrictions and rule bindings are simplified inside; any other node type, subclasses included, is kept as it is.
- **Rule engine opt-in**: `DynamicSpecificationEngine::withSimplification(bool $enabled = true)` (returns a copy of the engine, like `withCatalogValidation()`) and `isSimplificationEnabled()`. When enabled, `compileSpecification()`, and therefore `validate()`, return the simplified tree; every rule binding is kept, so the verdict and the reported rule failures are the same. Disabled by default. The SQL, TCriteria and ALinq visitors never simplify by themselves.
- **State machine deadlines read from the context.** `deadline()` takes exactly one source: `after` (a fixed ISO-8601 duration, as in 1.8.0), `afterFrom` (a context path holding an ISO-8601 duration or a `DateInterval`) or `atFrom` (a context path holding the due instant: a `DateTimeInterface` or an ISO-8601 text with date, time and offset). Paths start with `context.` and use the dot notation of the `PropertyAccessor`; the value is read from the context given to `transition()`/`initialSnapshot()` when the state is entered, so the core stays pure. Builder: `->deadline(event: 'SLA_BREACHED', atFrom: 'context.sla_due_at')`; array/JSON form: `{"atFrom": "context.sla_due_at", "event": "SLA_BREACHED"}`. A definition without the new fields keeps its 1.8.0 array form and fingerprint.
- **A missing or invalid deadline source is a rejection** (`TransitionResult::CODE_DEADLINE_SOURCE_INVALID`, `SM_DEADLINE_SOURCE_INVALID`, severity `ERROR`), never a silently empty deadline. The failure names the path, region and state, never the value read. Relative texts (`tomorrow`), instants without offset, impossible dates and negative durations are refused. A deadline that declares no source or more than one is refused when the definition is built (`InvalidMachineDefinitionException`, kind `invalid_deadline`).
- **Deadline pause with balance**: `deadline(..., pausedWhile: <guard expression>)`, where a `'region.state'` string is a shorthand for `inState`. It is evaluated after every accepted step, including the start and targetless transitions: when it starts to hold, the region's due instant becomes null and the remaining whole seconds are kept (an overdue deadline keeps zero and resumes already due); when it stops holding, the deadline resumes at `occurredAt + remaining`. Re-entering the state restarts the deadline and drops the balance. A pause condition that throws rejects the step (`ERROR`, `evaluation_error`). A paused region is never returned by `findDue()`. `MachineSnapshot` gains `pausedRemaining()`, `isPaused()`, `getPausedRemaining()` and `withPaused()`; its array form carries `paused_remaining` only while some region is paused, so a 1.8.0 snapshot loads and a snapshot that never paused keeps the 1.8.0 form.
- **Validator**: refuses a `pausedWhile` with a guard without factory, an `inState` path that does not exist or a guard whose factory fails; warns (`MachineDefinitionWarning::KIND_SELF_REFERENCING_PAUSE`) when the pause references the deadline's own region, since such a pause would never end.
- **Context provider for `MachineRunner::deliverDue()`**: a fifth, optional parameter `?Closure $contextProvider`, called with the `DueDeadline` and the loaded `MachineInstance`, returning the domain context of that delivery. A deadline transition that enters a state whose deadline reads the context, or a pause condition that reads it, needs it. Without it the context is null, as in 1.8.0.
- **Reference DDL**: nullable column `paused_remaining INTEGER` in `state_machine_region` (the balance of a paused deadline, whose `due_at` is then `NULL`), projected by both stores. The PDO store only writes it for a paused region.
- `StateMachine::START_EVENT` (`'machine.start'`), the internal event type a pause condition sees at the start.

### Changed

- **`StateMachine::initialSnapshot()` and `MachineRunner::start()` can now return a REJECTED result.** Before → after: the start was always accepted → it is rejected when an initial state's deadline reads a missing or invalid context source (`SM_DEADLINE_SOURCE_INVALID`) or its pause condition throws; `start()` then writes nothing (no instance, history or outbox row). Definitions that only use `after` are unaffected. Code that uses the new sources should check `isAccepted()` on the result of `start()`.
- **`DeadlineDefinition::$after` is now `?string`** (was `string`): it is null when the deadline reads its source from the context. `dueFrom()` throws a `LogicException` for such a deadline; `resolveDue($enteredAt, $context)` covers the three sources. The 1.8.0 call `new DeadlineDefinition('P3D', 'EXPIRE')` is unchanged.
- **`MachineRunner::migrate()` refuses a stranded pause.** Before → after: a migration whose target declares the current states was accepted → a migration that would leave a paused balance in a state whose deadline declares no `pausedWhile` is refused with `MachineMigrationException`, because the region could never resume and would stay without a deadline; the migration must resume the deadline or drop the balance.
- **`suggest` for `antevemus/alinq-collection`: `^1.4.1` → `^1.4.2`** (`composer.json` and README).

### Upgrading

- A database created with the 1.8 reference DDL needs the new column once, before the first deadline pause (`CREATE TABLE IF NOT EXISTS` does not add columns to an existing table):

  ```sql
  ALTER TABLE state_machine_region ADD COLUMN paused_remaining INTEGER;
  ```

  Until then every definition that never pauses a deadline keeps working on the old table; the first pause fails with `MachinePersistenceException` and its step is rolled back.

### Caveats

- **The equivalence of `simplify()` holds for non-null candidates**, the same premise as `isTautology()`/`isContradiction()`: `AND`/`OR`/`NOT` reject `null` whatever their operands, while the node left after simplification answers for `null` on its own (`alwaysTrue()->and(alwaysTrue())` rejects it, `alwaysTrue()` accepts it).
- **Truth value only**: removing a redundant branch may remove one that would have raised an exception; nothing else is promised.
- **Default messages of unannotated nodes may change** after simplification; only the messages and codes set with `because()`/`withCode()` are guaranteed.

## [1.8.0] - 2026-10-10

Two new namespaces, one security hardening and one fix (MINOR): a state machine whose guards are specifications (`StateMachine\*`, with its runner, persistence ports and reference DDL), and use cases whose result has the same shape as the machine's (`UseCase\*`, `Results\IOutcome`). No existing signature changes and no new Composer dependency. `RequirementState`, the document requirement state machine announced by 1.0.0 and reserved since 1.5.0, ships as what it always was: a machine definition (README example 14.4).

### Added

- **Specification-driven state machine** (`Antevemus\ASpecification\StateMachine`). Every guard is an `ISpecification`, so a denied transition returns why (the code, message, property and severity of the specification that blocked it) instead of a bare `false`.
  - **Definition as data.** `MachineBuilder` (`Spec::machine($key, $version)`): regions, states, final states, state-level transitions and region-level ones (`onAnyState()`, valid from any non-final state of the region, lower priority than the state's own), guards, named actions (`entry`, `exit`, transition `action()`), persisted deadlines (`deadline('P3D', 'EXPIRE')`, ISO-8601) and internal-only transitions. `MachineDefinition` is immutable, round-trips through `toArray()`/`fromArray()` and `toJson()`/`fromJson()` without loss, generates transition ids as `region.state.EVENT`, refuses at construction duplicate names or ids and integer-like names (PHP would turn them into integer keys), and has a deterministic `fingerprint()` (SHA-256 of the canonical form, independent of key order). Guards and actions are referenced by name and JSON-friendly parameters, never by closures: `GuardExpression` trees (`ref()`, `allOf()`, `anyOf()`, `not()`) where any node may carry its own `because()`/`withCode()`.
  - **Guards.** `GuardRegistry` (`Spec::guardRegistry()`) maps a name to a factory `(array $params): ISpecification`, in the spirit of the rule engine's registry, with three built-ins: `inState` (`{"state": "region.state"}`, reads another region), `payloadHas` (`{"field": "motive"}`) and `eventOrigin`. The candidate is a `TransitionCandidate` (`context` = the caller's domain object or array, `event`, `snapshot`). Guards are pure: "now" is the event's `occurredAt`, the machine never reads the clock.
  - **Validator.** `MachineDefinitionValidator::validate()`/`analyze()` (`Spec::validateMachine()`) refuses a definition with one `InvalidMachineDefinitionException` listing every error (region without or with unknown initial state, unknown or cross-region target, `inState` to an unknown state, guard without factory or whose factory throws with the declared parameters, action without handler when the known names are given, final state with outgoing transitions) and returns `MachineDefinitionWarning`s without blocking: `unreachable_state`, `dead_end_state` (non-final without exit), `overlapping_guards` (same event and state, not proven disjoint by the 1.6.0 algebra, only where the algebra decides), `shadowed_transition` (an unguarded transition before another one for the same event) and `tautological_guard`.
  - **Pure core.** `StateMachine` (`Spec::stateMachine()`): `initialSnapshot()`, `transition()`, `can()` (the same call, no side effect) and `nextEvents()` (every answerable event with its result, so a disabled button can show its reason). No I/O, clock or randomness, inputs never mutated. Semantics: event first, candidates in declaration order and the first whose guard passes wins; guards read the snapshot from before the event in every region; an event is all or nothing across regions (`accepted`, `rejected` with the reason of every candidate tried and `getRejections()` per region, or `unhandled` with `SM_UNHANDLED_EVENT`); a guard that throws is an `ERROR` failure marked `evaluation_error` and stops the selection in its region; effects in SCXML order (every `exit`, then every transition action, then every `entry`); a transition to the same state re-enters it, a targetless one only runs its actions. The machine is done when every region that declares a final state is in one (a region without final states, such as a pending flag, does not hold it open), and a done machine is inert (`SM_MACHINE_DONE`). A deadline event and transitions declared internal only accept internal events (`SM_INTERNAL_EVENT`), and a deadline event is only accepted once due (`SM_DEADLINE_NOT_DUE`). `MachineSnapshot` and `Event` (`external()`/`internal()`, payload, optional idempotency key) are immutable.
- **Runner, persistence and reference DDL.**
  - `Runner\MachineRunner`, the single write port: `start()`, `send()` (load → idempotency check → optional `expectedVersion` → pure transition → compare-and-set of the snapshot version, one history row per region moved, effects in the outbox, idempotency record → commit, all in one transaction), `load()`, `can()`, `nextEvents()`, `registerMigration()`/`migrate()` (an instance stays pinned to the definition version it started with; moving it is explicit), `findDue()`/`deliverDue()` (deadline event sent with internal origin and a deterministic idempotency key, so a late or repeated delivery is harmless). A lost compare-and-set throws `ConcurrencyConflictException` and is never retried silently; a key already processed returns the original result and writes nothing; rejected and unhandled events write nothing (except the optional rejection log).
  - Effects after the commit: `EffectHandlerRegistry` (`register()`, and `registerSync()` for the rare effect that must be able to veto: it runs inside the transaction and an exception rolls the step back, `SyncEffectFailedException`) and `EffectDispatcher::dispatchPending()` (FIFO per instance, a failure holds the instance's later effects back, optional `maxAttempts`, at-least-once, the handler receives the effect's idempotency key, the last error is kept without stack trace); a failing handler never undoes the transition.
  - Ports `IMachineInstanceStore`, `IMachineHistoryStore` (append-only), `IEffectOutbox`, `IIdempotencyStore`, `IMachineRejectionLog` (off by default), `ITransactionManager`, `IMachineDefinitionRepository` (`InMemoryMachineDefinitionRepository` refuses a different definition under the same key and version), bundled by `MachinePersistence::inMemory()` and `MachinePersistence::pdo($pdo, $schema, $tables, $columns)` (table names by role and real column names by canonical column; on a connection already inside a transaction the PDO stores join it and its owner commits). Both sets run the same test battery.
  - `resources/sql/state_machine.ansi.sql`: six tables (`state_machine_instance`, `_region`, `_history`, `_outbox`, `_idempotency`, `_rejection`), portable SQL, `CREATE TABLE IF NOT EXISTS`, a primary key on every table, `UNIQUE (instance_id, idempotency_key)`, instants as fixed-width UTC text (`VARCHAR(26)`), JSON columns as `VARCHAR(4000)` (the portable size that fits Oracle; widen to `TEXT`/`JSONB`/`CLOB` for larger payloads), no `CREATE INDEX` (lookup indexes are `UNIQUE` constraints with the searched columns first). Due deadlines are searched with a specification compiled to SQL by the SQL visitor.
- **Use cases** (`Antevemus\ASpecification\UseCase`): `IUseCase` (one method, `execute(object $request): UseCaseResult`); `UseCaseRunner` (`Spec::useCaseRunner()`): middlewares in registration order, request validation by its `#[ValidateRule]`/`#[AssertSpec]` attributes plus the specifications registered for its class (`registerRequestSpecification()`), only an `ERROR` failure blocks (`INVALID`, `execute()` not called) while `WARNING`/`INFO` come back with the result, and any unhandled exception becomes `FAILED` (`UNHANDLED_EXCEPTION`, generic message) and goes to an optional `IUseCaseErrorReporter`, never into the result (no message, class, file, line or stack trace); `UseCaseResult`, final and immutable, with factories (`success`, `created`, `accepted`, `noChange`, `invalid`, `rejected`, `notFound`, `conflict`, `forbidden`, `failed`), coherence checks (no success with an `ERROR`, no failure status without a failure) and `fromTransition()`/`fromConcurrencyConflict()`; `UseCaseStatus`, ten closed domain statuses, success derived from the status alone, HTTP only in `toHttpStatus()` (closed map, no way back from an integer); `TransactionMiddleware` (commit on success, rollback on a failure status or an exception, which it rethrows) and `CallableMiddleware`; `StateMachineEventUseCase` (`Spec::machineEventUseCase()`) with `MachineEventRequest`, exposing a machine event as a use case (accepted → `SUCCESS` with the snapshot, rejected → `REJECTED` with the guards' codes, unhandled → `CONFLICT`, stale version → `CONFLICT` with `SM_CONCURRENCY_CONFLICT`, unknown instance → `NOT_FOUND`). No mediator, container or handler discovery.
- **`Results\IOutcome`** (`isSuccess()`, `getReason()`): the shape shared by `UseCaseResult` and `TransitionResult`.
- **Facade entry points** on `Spec`: `machine()`, `guardRegistry()`, `stateMachine()`, `validateMachine()`, `useCaseRunner()`, `machineEventUseCase()`.
- **Deliberately out of scope**, so readers know it is a choice and not a gap: actors (`invoke`, `spawn`, `sendTo`; asynchronous work is an external job that sends an event back), eventless transitions (`always`) and `raise` (the caller sends the next event), nested states inside a region and history states (a parallel region covers the real cases), a machine-owned context (`assign`; the context is the caller's domain object), and event sourcing as the source of truth (the history is a trail, the snapshot is the truth).
- Provenance: Stately/XState (MIT) and TheFlow by Elemar Jr. (Apache-2.0) were conceptual references for the state machine, and the Use Case Interactor pattern of Clean Architecture for the use cases; no code was ported (`NOTICE.md`, section 4).

### Security

- **An exception raised while evaluating a rule no longer reaches the failure.** Failures are what applications show to users, but an evaluation error (a specification, a rule handler, a state machine guard or an annotated getter that throws) copied the exception message into `SpecificationFailure::$message` and the exception class into `metadata['evaluation_error']`, so a database error, a file path or a value inside the message could end up on a screen or in an API response. **Before → after**, for a failure produced by `SpecificationResult::error()` (and by `AttributeValidator`, which follows it): `$failure->message` the exception message (or its class when empty) → `SpecificationResult::EVALUATION_ERROR_MESSAGE` (`'The rule could not be evaluated.'`); `metadata['evaluation_error']` the exception class → `true`. The code, rule name, property, severity (`ERROR`) and `isError` are unchanged, and the exception itself is still on `SpecificationResult::$exception`, for the caller to log. Code that read the failure message to learn the technical cause must read `$result->exception` instead. Recommended practice (README, section 2): log `$result->exception` with your own logger, taking care not to log more than needed, and show users only the failure message, never the metadata (it may hold the evaluated value, for example `metadata['actual']`).

### Fixed

- **The severity declared on an attribute now reaches the failure's `severity` field.** Since 1.5.0 `SpecificationFailure` carries a `FailureSeverity`, but `AttributeValidator` (`Spec::validateAttributes()`, `Spec::assertAttributes()`) only wrote the attribute's `severity` string into `metadata['severity']` and left the field `null`, so code reading `$failure->severity` or `getSeverity()` could not tell a warning from an error. **Before → after**, for a failure of `#[ValidateRule(..., severity: 'WARNING')]` or `#[AssertSpec(..., severity: 'WARNING')]`: `$failure->severity` `null` → `FailureSeverity::WARNING` (likewise `'ERROR'` → `ERROR`, `'INFO'` → `INFO`, case and surrounding spaces ignored). An unknown value is `ERROR`, so a typo never turns a blocking rule into a warning; an evaluation error (a specification or an annotated getter that throws) is always `ERROR`. `metadata['severity']` is unchanged. Affects 1.5.0 up to 1.7.0.

## [1.6.1] - 2026-10-10

Security patch. Access by name to private and protected properties, added in 1.4.4 for Domian parity, becomes opt-in by the author of the class through the new `#[Specifiable]` attribute. One declared behaviour change, for code that read or wrote unmarked non-public properties by name.

### Security

- **Private and protected properties are reached by name only when marked `#[Specifiable]`.** Since 1.4.4 the `PropertyAccessor` read any private or protected property, declared anywhere in the class hierarchy, as its last resolution step, and `updateWithDelta()` (`SpecificationHelper::updateEntityState()`) wrote any of them when the entity had no public setter. The library only receives a property name as text and cannot tell a domain rule written by the author of the entity from a name that came from a request (a filter or an ordering built by a screen). So (1) **reading worked as an oracle**: a range or a prefix over a private field (`Spec::property('password_hash', Spec::greaterThanOrEqualTo('a')->and(Spec::lessThan('b')))`, `Spec::property('password_hash', Spec::startsWith('a'))`) revealed its value character by character through which candidates passed the filter; (2) **writing worked as mass assignment**: a delta built from request fields set a private field directly, skipping the setter and its invariants. The decision of the author to keep a property private holds again; the author marks what is specifiable. **Before → after**, on a private or protected property without accessor and without the marker: `Spec::property('passwordHash', $spec)->isSatisfiedBy($entity)` read the field → throws `InvalidArgumentException` (`Property "passwordHash" not found or not accessible ...`, the same answer as for a missing property, whatever the range; `evaluate()` returns an error state and `not()` does not approve it; the ALinq visitor mirrors it); `PropertyAccessor::hasProperty()` `true` → `false` and `getValue()` the value → `null`; `updateWithDelta($entity, Spec::property('passwordHash', Spec::is('x')))` wrote the field → `InvalidArgumentException` (`Property "passwordHash" of Foo is not public and not marked #[Specifiable]; it cannot be written by a delta specification`). The protected `AbstractCompositeSpecification::getPropertyValue()` follows the same rule in its reflection fallback (an unmarked property is "not found"). `StrictReturnsNullFactory` never wrote private state, but it checks the built object against the specification, so it now returns `null` for a class whose private fields have neither getter nor marker. **Unchanged:** the earlier resolution steps and their order (array or `ArrayAccess` key, public `getX()`/`x()`/`isX()`/`hasX()`, `__get` guarded by `__isset`, public property), public setters in a delta (a private property with a public setter needs no marker), public properties, and the explicit utilities `ReflectionUtils::getFieldByName()`/`getFieldValue()`/`setFieldValue()`, which code calls by its own decision. **Migration:** mark with `#[Specifiable]` each non-public property that rules are meant to reach by name (or the class, for every property it declares), or give it a public getter/setter.

### Added

- **`Attributes\Specifiable`** (`#[Attribute(Attribute::TARGET_PROPERTY | Attribute::TARGET_CLASS)]`): on a property, makes that private or protected property readable by name and writable by a delta; on a class, the same for every property **declared by that class** (it does not reach the properties of a parent class nor of a subclass). `#[Antevemus\ALinq\Attributes\Specifiable]` (ALinq 1.4.1) is accepted as the same marker, recognized by name, so the ALinq package is not a dependency. `ReflectionUtils::isSpecifiable(ReflectionProperty): bool` and `ReflectionUtils::SPECIFIABLE_ATTRIBUTES` expose the check.

### Documentation

- README (EN and pt-BR): the release badge, which still read v1.4.3, now reads v1.6.1. Section 10.1: the resolution order and the opt-in, with an example (one marked and one unmarked private property) transcribed as a test in Module 14; directory tree; runner block (16 suites, 2 877 assertions) and PHPUnit counts (237 tests, 5 006 assertions; Domian Parity 219 tests, 2 106 assertions).

## [1.6.0] - 2026-10-09

Algebra and announced backlog II (ROADMAP milestones 9, 10 and 11; Reversa forwards 018, 019 and 020). Two declared contract extensions (`ISpecification`, `IVolatileRepository`); no other breaking change.

### Added

- **Tautology and contradiction detection** (forward 019): `isTautology()` and `isContradiction()` on every specification, plus `Spec::isTautology()`/`Spec::isContradiction()`. Structural and conservative: `true` only when the shape of the tree proves it, `false` means "not proven", never "proven otherwise"; no SAT solving, `evaluate()` is untouched. Proven: `alwaysTrue()`/`alwaysFalse()`, `not()` swapping the two, flattened conjunctions with a contradictory child, a complementary pair (`A ∧ ¬A`, by structural `equals()`) or a disjoint pair (`isDisjointWith()`: `equalTo('A') ∧ equalTo('B')` on the same property, an inverted `between()`), the mirror rules on disjunctions (`A ∨ ¬A`), NOR as `¬(a ∨ b)`, `where()` inheriting contradiction only, `in([])`. A truth-table test (1 500 random trees over two leaf sets, every candidate, fixed seed) guards soundness. Cost is O(n²) per node. The rule engine gains a **catalog validation mode** (`DynamicSpecificationEngine::withCatalogValidation()`, `isCatalogValidationEnabled()`, `getCompilationWarnings()`) that reports every compiled rule that can never pass or never fail as a `RuleCompilationWarning` (`kind`, `ruleCode`, `ruleType`, `message`, `specification`), without blocking and without touching the verdict. README example 12 is the test.
- **`MethodParameterizedSpecification`** (forward 018; `Specifications/Reflection/`): a leaf that calls a public method of the candidate with arguments declared as data (scalars, `null`, arrays, `BackedEnum`, `DateTimeInterface`; closures, arbitrary objects, resources and pure enums are refused at construction) and applies a specification to the result. Unlike `must(closure)` it has structural `equals()`, a rule name `method(...)` and can be described in a catalog. A missing or non-public method is a `BadMethodCallException` in `isSatisfiedBy()` and an error state in `evaluate()` (never a silent `false`); a `null` result does not satisfy, as `where()`. Built by `Spec::calling()`, the DSL `calling()` and `ISpecification::whereMethod()` (chainable like `where()`). The SQL and TCriteria visitors refuse it as a non-translatable leaf; the ALinq visitor compiles the call with the same semantics. The Domian `FieldParameterizedSpecification` is deliberately not built: `where()` is the field half, private fields included since 1.4.4. README example 13 is the test. Declarative construction from a rule catalog (forward 018 RN-08) is deferred: the core has no specification serialization yet (ROADMAP milestone 16).
- **TTL and auto-prune on volatile repositories** (forward 020 RN-05): `IVolatileRepository::withTtl(int $seconds): static` and `prune(): int`. The TTL counts from the last write; an expired entry is invisible to every read (`find*`, `iterate`, `count`, `findSingle`, `contains`, `getAll`, `removeAll`), scans evict it on the way, `prune()` evicts and counts; `withTtl(0)` disables, a negative value throws; `getTtl()` and an injectable `withClock(?Closure)` for tests. `VolatilePartitionRepository` applies the TTL to the whole subtree and partitions created later inherit it; `NullRepository` accepts it and keeps nothing. Announced by the 1.0.0 CHANGELOG and never shipped.
- **Materialised partition DAG index** (forward 020 RN-06): `PartitionRepository` keeps the topological order and the parent/child lists, invalidated on every structural change, and walks it in `findAll`/`iterate`/`remove`/`removeAll`/`contains` with the exact order of the recursive walk (a graph changed during an iteration falls back to the recursive walk, so late partitions are still visited; a user subclass keeps the recursive walk). Benchmark (`tests/Benchmark/dag_index_benchmark.php`, report in `tests/Benchmark/REPORT-dag-index.md`, 20 000 entities, 200 partitions in 4 levels): `findAll` 45 % to 77 % faster, `put()` unchanged. The **routing clusters** of mutually disjoint siblings (route a `put()` without testing every sibling) are implemented but **off by default**: they cut evaluations per `put()` (15 → 10) with cheap leaves, but building them costs one `isDisjointWith()` per sibling pair, and for `in()` sets of 162 values that check alone measures 88 ms, so `put()` got 3 to 6 times slower with library specifications. `PartitionRepository::setDagIndexEnabled()`/`isDagIndexEnabled()` and `setDagRoutingEnabled()`/`isDagRoutingEnabled()` switch each part.
- **Three SQL dialects** (forward 020 RN-07): `SqlDialect::DB2` (drivers `db2`, `ibm`, `ibm_db2`, `pdo_ibm`: upper-case quoted identifiers, booleans `1`/`0`, `LOWER()` for case-insensitive `LIKE`, `REGEXP_LIKE(..., 'c'|'i')`, `FETCH FIRST n ROWS ONLY`/`OFFSET m ROWS`), `INFORMIX` (`informix`, `ifx`, `pdo_informix`: identifiers unquoted by default because without `DELIMIDENT` Informix reads `"col"` as a string literal, `delimitedIdentifiers: true` quotes in lower case; booleans `'t'`/`'f'`; regex refused with `UnsupportedSqlOperationException`; `SKIP m FIRST n`) and `DUCKDB` (`duckdb`, `pdo_duckdb`: case-preserving quotes, `TRUE`/`FALSE`, `ILIKE`, `regexp_matches(col, :p[, 'i'])`, `LIMIT`/`OFFSET`). **12 drivers over 7 dialects → 15 drivers over 10 dialects.** Announced by the 1.0.0 CHANGELOG and never shipped.
- **Pagination on every dialect**: new `ISqlPagination::paginate(string $sql, ?int $limit, ?int $offset): string`, implemented by `AbstractSqlDialect` for the ten dialects (`OFFSET m ROWS FETCH FIRST n ROWS ONLY` on ANSI, Oracle 12c+, Firebird 3+ and Db2; `LIMIT n OFFSET m` on PostgreSQL, MySQL, SQLite and DuckDB, with `LIMIT 18446744073709551615`/`LIMIT -1` when only an offset is given; `OFFSET ... FETCH NEXT` with `ORDER BY (SELECT NULL)` added when missing on SQL Server; `SKIP`/`FIRST` on Informix); limit ≥ 1, offset ≥ 0. Executed against an in-memory SQLite in the tests.
- `SpecificationAlgebra` public helpers: `flattenConjunction()`, `flattenDisjunction()`, `isContradictoryConjunction()`, `isTautologicalConjunction()`, `isTautologicalDisjunction()`, `isContradictoryDisjunction()`, `areComplementary()`, `areTypesDisjoint()`.

### Changed

- **Contract extension (breaking only for classes implementing `ISpecification` without extending `AbstractSpecification`):** `ISpecification` gains `isTautology()`, `isContradiction()` and `whereMethod()`. Reference defaults: `return false;`, `return false;` and `return $this->and(new MethodParameterizedSpecification($method, $arguments, $result, $this->getType()));`. `IVolatileRepository` gains `withTtl()` and `prune()` (same precedent as `contains()` in 1.5.0): an external class implementing it directly must add both.

### Fixed

- **False disjointness removed from the algebra** (found while proving the detection rules; the Domian parity suite stays green). Two unrelated interfaces were declared disjoint (`specify(IFoo)->isDisjointWith(specify(IBar))` `true` → `false`: a class may implement both), a typed specification was declared disjoint from any value-bound leaf whose value is not an instance of the type (`specify(DateTimeImmutable) ⟂ greaterThan(new DateTime(...))` and `specify(T) ⟂ notEqual(null)` `true` → `false`; disjointness is now claimed only where the comparison would throw for every `T`), and `atTheSameTimeAs()` no longer bounds the candidate's class (`specify(DateTimeImmutable)->isGeneralizationOf(atTheSameTimeAs($d))` `true` → `false`).

## [1.5.0] - 2026-10-09

README Promises II (ROADMAP milestone 6, Reversa forward 017) and the first half of the announced-but-unshipped backlog (milestones 7 and 8, forward 020). Two declared breaking changes: Unicode case folding and `in()` becoming its own leaf.

### Added

- **`SysVSemaphoreSynchronizer`** (`src/Concurrent/`): the inter-process reader/writer lock the README promised, on SysV IPC semaphores (`ext-sysvsem`, Linux/Unix). `new SysVSemaphoreSynchronizer(string $name, int $maxPermits = 10000, int $permissions = 0666)`: two semaphores (a permit counter and a binary writer lock, writer preference), keys derived from the name (`keyFor()`), permits released on `release()`/`__destruct` and undone by the kernel if the process dies (`SEM_UNDO`), `remove()` deletes the set, reentrant per Fiber like the in-process class. Without the extension the constructor throws `RuntimeException` pointing to `SemaphoreSynchronizer`, which stays intra-process (its DocBlock says so now). Tested with a child process (`pcntl_fork`/`proc_open`), skipped where the extension is missing. Any repository accepts it: `new InMemoryRepository([], null, new SysVSemaphoreSynchronizer('customers', 8))`.
- **`InSpecification`** (`Specifications/Comparison/`): `in()` is a leaf of its own with strict typed identity (`===` against each member, `null` matches only as a member, a candidate comparable to no member raises `IncompatibleTypeException` like `equalTo()`), set equality, `getType()` `DateTimeInterface` when every member is a date, and algebra on every node: `X ⊇ in(V)` iff `X ⊇ equalTo(v)` for every `v`, `X ⟂ in(V)` iff `X ⟂ equalTo(v)` for every `v` (so `in` × `in` by subset/intersection, `greaterThan(3) ⊇ in(4, 5)`, `notEqualTo(3) ⊇ in(1, 2)`), `in([])` is the empty leaf: never satisfied, disjoint with everything, generalized by everything. `Spec::notIn()`, DSL `notIn()` and `SpecificationFactory::notIn()` (= `not(in(...))`). Translated by the three visitors: SQL `"col" IN (:p1, :p2)` (`null` member adds `OR "col" IS NULL`, empty set is the dialect's false form `1 = 0`), TCriteria `TFilter('col', 'IN', [...])`/`'NOT IN'`, ALinq strict `in_array()`.
- **Lazy sources everywhere**: `AbstractRepository::asLazyCollection()` and `findAsLazyCollection()` on every repository of the library (previously `InMemoryRepository` only), built on `IRepository::iterate()` through a callable that yields a fresh generator per traversal, so the ALinq collection stays re-iterable and `getAll()` is never called; `filterLazy()` over a repository filters through `iterate($spec)`, so partition pruning applies.
- **`Engine\PdoRuleCatalog`**: an `IRuleCatalog` read from the relational rule and document tables through PDO, in portable ANSI SQL (`active = 'Y'`, scope, scenario, product/plan applicability as the `IRuleCatalog` contract requires, optional validity window through the immutable `withAsOf()`), with configurable schema and table names (defaults `regra_negocio`, `grupo_documento_obrigatorio`, `grupo_documento_obrigatorio_tipo`). The SQL narrows the rows; the final applicability pass and the ordering reuse `InMemoryRuleCatalog`, so the same rules in memory and in the database produce the same verdict (tested on SQLite with the reference DDL `resources/sql/rule_catalog.ansi.sql`, which lists only the columns the engine reads). Previously the engine only had `InMemoryRuleCatalog` and `fromArray()`.
- **`Results\FailureSeverity`** (`ERROR`, `WARNING`, `INFO`): `SpecificationFailure` carries an optional severity (`getSeverity()`, `withSeverity()`, `SpecificationResult::failure(..., severity:)`), and the rule engine fills it from the effective action (`RuleAction::toSeverity()`: `bloquear` → ERROR, `alertar` → WARNING, `apenas_log` → INFO; the handler's action wins over the rule's, evaluation errors and document failures are ERROR). `hasBlockingErrors()` is unchanged. Announced by the 1.0.0 CHANGELOG and never shipped.
- **`Entities\AbstractUlidEntity` and `AbstractUuidV7Entity`** with `Util\UlidGenerator` (Crockford base32, 26 chars, monotonic within the millisecond, `OverflowException` when the 80 random bits overflow) and `Util\UuidV7Generator` (RFC 9562, 74-bit counter, advances one millisecond on overflow); injectable clock, `shared()`, `isValid()`, `timestampOf()`. Announced by the 1.0.0 CHANGELOG as ULID/UUID v7 identities and never shipped.

### Changed

- **Unicode case folding (breaking).** `equalIgnoreCase()` and `wildcardIgnoreCase()` (and the ALinq visitor shortcut) compare with `mb_strtolower()` in UTF-8 instead of `strcasecmp()`/`strtolower()` (ASCII only). **Before → after:** `Spec::equalIgnoreCase('ÁGUA')->isSatisfiedBy('água')` `false` → `true`. An accent is still a different letter (`'ÀGUA'` does not match `'água'`) and `ß` does not fold to `ss`. `fnmatch()` works per byte, so `?` does not match a multibyte character: use `*`. `ext-mbstring` moves from `suggest` to `require`.
- **`in()` is a leaf (breaking for code inspecting the tree or the generated SQL).** `in(1, 2)` was an `OrSpecification` of `EqualSpecification`, `in([])` was `AlwaysFalseSpecification`; both are `InSpecification` now, `equals()` compares sets, the failure `ruleName` is `InSpecification`, SQL `("c" = :p1 OR "c" = :p2)` becomes `"c" IN (:p1, :p2)`, TCriteria emits `IN` instead of an `OR` chain, and a mixed set no longer throws depending on member order (`in(1, 'a')->isSatisfiedBy('a')` was an exception, now `true`). `NOT ("c" IN (...))` keeps SQL three-valued logic (rows with `NULL` are not returned), as the `OR` chain did.

## [1.4.4] - 2026-10-09

Domian parity correction lot. A method-by-method audit of this library against the Domian trunk (r1209; 103 main sources in 6 modules, two of them never inventoried before) found that the subsumption algebra and the partition DAG did not behave as the Java reference and as the README promised. The Java tests were transcribed into `tests/Parity/` (213 tests, 2 043 assertions, a new PHPUnit suite "Domian Parity"); the audit reports and reproducible probes live in `docs/paridade-domian-2026-10-09/` and the consolidated findings in `docs/PARIDADE-DOMIAN-2026-10-09.md`. No public signature changes.

### Fixed

- **Subsumption algebra.** `isGeneralizationOf()`, `isSpecialCaseOf()`, `isDisjointWith()` and `intersectsWith()` now follow the Domian rules on every node: `and(A, B) ⊇ X` iff both sides generalize `X`; `X ⊇ and(A, B)` if either side is generalized; `or(A, B) ⊇ X` if either side generalizes `X` (previously **both** were required, so `A ⊂ or(A, B)` was `false`); `X ⊇ or(A, B)` iff both; `not(A) ⊇ not(B)` iff `B ⊇ A`; `A ⟂ not(A)`; reflexivity; `specify(Sub) ⊂ specify(Super)` by class hierarchy; `specify(T) ⊇ specify(T)->where(...)`; `adult ⊇ adult->and(pioneer)`; interval arithmetic on value-bound leaves of the same property (`gte(5) ⊇ gt(5)`, `lt(5) ⟂ gte(5)`, `isBefore(2020) ⊇ isBefore(2010)`, `after(A) ⟂ before(A)`, `isNull ⟂ isNotNull`, `not(lt(10)) ⟂ lt(10)`, integer gaps such as `gt(10) ⟂ lt(11)`); `NotNull` generalizes everything; `AlwaysTrue`/`AlwaysFalse` are leaves that resolve negations. Previously the composite default returned `equals()` only, so `all(Customer) ⊇ all(VipCustomer)` and `(A and B) ⊂ A` were `false` (37 of 61 assertions of the audit probe diverged; 2 remain, both deliberate, see below). **Before → after:** `Spec::specify(Customer::class)->isGeneralizationOf(Spec::specify(VipCustomer::class))` `false` → `true`.
- **Structural `equals()`.** Composite specifications and `Spec::specify(T)` compared object identity (two `Spec::specify(Customer::class)` were never equal, and a partition "equal" to an existing one was duplicated instead of reused). They now compare structure: class, type, children as an unordered set, `because()`/`withCode()`; property leaves by base, name and inner; value-bound leaves by class and value (dates by instant). `and()`/`or()` with an equal specification return the same instance. **Before → after:** `Spec::specify(T)->equals(Spec::specify(T))` `false` → `true`.
- **Named leaves instead of anonymous classes.** `greaterThanOrEqualTo()`/`atLeast()`, `lessThanOrEqualTo()`/`atMost()` return `GreaterThanOrEqualSpecification`/`LessThanOrEqualSpecification` (previously `or(gt, eq)`: the SQL and TCriteria visitors emitted `(x > :p OR x = :p)`, now `x >= :p`, and `evaluate()` reports one failure instead of two causes); `isNull()` returns `IsNullSpecification` (translated as `IS NULL`; previously untranslatable); `before()`, `after()`, `at()`, `beforeOrAt()`, `afterOrAt()` return value-bound leaves with `getValue()` and subsumption, `between(a, b)` is `and(gte(a), lte(b))`; `GreaterThan`/`LessThan` accept `DateTimeInterface`; the date leaves clone a mutable `DateTime` so the specification no longer changes when the original object is mutated.
- **Partition DAG (`PartitionRepository`).** Inserting a partition that generalizes existing ones re-wires the existing node under the new one (previously the node was recreated with its underlying repository only and its sub-partitions were lost: `findPartition()` stopped finding them); `findPartition()` descends by generalization to the most specific partition that generalizes the specification (previously equality only, so a narrower specification returned `null`); a specification that is a special case of two siblings becomes one node referenced by both parents (previously two nodes over the same repository, and `getAllPartitions()` counted it twice); `repartition()` of an entity that is not stored returns `false` without storing it (previously inserted it) and `true` when the entity already resides in the right partition; `put()` on a non-root partition with an entity outside its boundary delegates to the root, which routes it, and the root throws `InvalidArgumentException` when no partition accepts the entity (previously the entity stayed in the wrong repository); a sibling added after the entities receives the ones that satisfy it; iteration is lazy (one evaluation before the first item instead of all); the same set of partitions produces the same graph whatever the insertion order (tested over every permutation); `update()`/`updateWithDelta()` reach every repository that holds the entity before repartitioning; `repartitionAll()` counts the entities that actually moved; `load()`/`store()`/`close()` of a persistent partition reach persistent repositories under volatile ones and visit a shared node once; `getEntitiesOfThisPartitionOnly()` lists what physically resides in the node. `collectPartitions()` additionally accepts a specification over repository objects (Domian `collectAllPartitionsWithRepositorySatisfying`).
- **Repositories are synchronized.** No repository used `ISynchronizer`. `AbstractRepository` and `InMemoryRepository` now carry one (`withSynchronizer()`, `setSynchronizer()`, `getSynchronizer()`, default `NullSynchronizer`; `InMemoryRepository::__construct(array $initialEntities = [], ?string $repositoryId = null, ?ISynchronizer $synchronizer = null)`), run reads under `callConcurrently()` and writes under `callExclusively()`. `SemaphoreSynchronizer` is reentrant per execution context (main flow or Fiber), as the Java thread-local: an exclusive section inside a concurrent one of the same owner no longer throws; real contention between contexts still throws, with a message explaining that a single PHP process cannot wait.
- **`updateWithDelta()` applies the delta** in every repository (memory, partition, single-file, file-per-entity, hybrid): each value-bound property clause of the delta writes the property (public setter, else the field by reflection, private and inherited included), a `JointDenial` clause writes `null`, `null` delta is `update()`, an entity of another type raises `InvalidArgumentException`. Previously the delta was ignored everywhere.
- **`AbstractEntity::equals()` checks the type**: `Customer(102)->equals(Order(102))` was `true`, now `false` (same family is still equal: `VipCustomer(5)` equals `Customer(5)`); `hashCode()`, `toString()`/`__toString()` added. `JointDenialSpecification::isSatisfiedBy(null)` `true` → `false`. `NotNullSpecification::isGeneralizationOf()` `false` → `true`.
- **`StopWatch`** matches the Java `StopWatchTest`: `start()` on a started watch no longer restarts it, stop/start accumulates, `lap()` on a stopped watch measures nothing; `getElapsedTime()`, `getLapTime()`, `elapsedTimeToString()`, `lapTimeToString()`, `toString()`, `print()` added. `InstrumentationUtils` gains the Domian constants and helpers (`prettyPrintLargeNumber()`, stack-trace helpers, memory and thread messages, `printPartitionRepository()`).
- **Private and protected properties are specifiable**: `Spec::property('own', ...)` on a private field without getter resolved to an error; the `PropertyAccessor` now reads non-public properties by reflection as the **last** step, after arrays/`ArrayAccess`, public getters, `__get` guarded by `__isset` and public initialized properties (the documented order is unchanged; `ReflectionUtils` added in `Helpers/`).

## [1.4.2] - 2026-10-08

### Fixed

- **TCriteria bridge: the `i` modifier of a regular expression survives.** `Spec::toCriteria()` dropped the PCRE modifiers together with the PHP delimiters, so `regex('/^abc/i')` and `regex('/^Abc/')` reached the database as the same `REGEXP '^abc'` / `'^Abc'`, and case sensitivity depended on the engine (MySQL's `REGEXP` is case-insensitive by default on non-binary columns, so the case-sensitive pattern was evaluated without case too). `TCriteria` has no dialect, so the flag now travels inside the pattern: `REGEXP '(?i)^abc'` for a pattern with `i`, `REGEXP '(?-i)^Abc'` without it, in plain and prepared mode and under `NOT`, verified against the real Adianti classes. `u` is accepted; any other modifier (`m`, `s`, `x`, ...) is refused with `NonTranslatableCriteriaException` naming it instead of being silently discarded, as the SQL visitor already did. The `REGEXP` operator itself remains what the Adianti `TFilter` can render: it works on MySQL 8 (ICU), MariaDB (PCRE) and SQLite with a registered PCRE function; on PostgreSQL, Oracle, Firebird and SQL Server use `toSql()` with the dialect.

## [1.4.1] - 2026-10-07

### Fixed

- **`#[AssertSpec]` / `#[ValidateRule]` on a getter that throws.** An exception thrown by the annotated getter itself, before its specification or rule is evaluated, no longer propagates raw from `Spec::validateAttributes()`: it becomes a failure carrying the exception message, the attribute `code`, the method name and `metadata['evaluation_error']`, the result reports `isError()` with the exception, the remaining attributes are still evaluated, and `assertAttributes()` throws `AttributeValidationException` with the cause chained (`getPrevious()`), exactly as an error while evaluating the specification already did. **Breaking for** code that caught the getter's exception around `validateAttributes()`: read `isError()` / `exception` on the result instead.
- **TCriteria bridge: `startsWith()`, `endsWith()` and `contains()` translate to `LIKE`.** `Spec::toCriteria()` emitted them as `REGEXP`, an operator missing in SQLite, Firebird, SQL Server and ANSI (`~` on PostgreSQL), and dropped the case-insensitive flag on the way. They now become `col LIKE 'Ab%'` / `'%Ab'` / `'%Ab%'`, `UPPER(col) LIKE UPPER('ab%')` when case-insensitive, `NOT LIKE` under negation, with `%`, `_` and `!` of the literal escaped and an `ESCAPE '!'` clause appended by a dedicated `TFilter` subclass, in plain and prepared mode, verified against the real Adianti classes. - **`like()` / `wildcard()` escape the literal `%`, `_` and `!` of the pattern** in the SQL visitor (every dialect) and in the TCriteria bridge, adding `ESCAPE '!'` only when needed (also when the pattern contains a backslash, MySQL's default escape). `Spec::like('100%*')` was bound as `100%%` and matched `1000x`, which the in-memory evaluation (`fnmatch`) never did; it is now `100!%%` with `ESCAPE '!'`. `*` and `?` remain the consumer's wildcards. Patterns without those characters produce exactly the same SQL as before.

### Added

- `Sql\LikePattern` (`@internal`): the LIKE escaping rule shared by the SQL and TCriteria translators. `Criteria\TEscapedLikeFilter` (`@internal`): `TFilter` that appends the `ESCAPE` clause after the parent's rendering.

- **Evaluation errors are no longer rule failures.** When a specification cannot be evaluated (missing property on the candidate, throwing getter, `TypeError` inside `isSatisfiedBy()`), `evaluate()` now returns an error result: `isSatisfied = false`, new `isError = true` and the exception attached in the new `exception` property (`SpecificationResult::error(...)`). `NOT` never inverts an error result, `AND`/`OR`/`combine()` propagate it, and `isSatisfiedBy()` keeps throwing. Previously the exception was downgraded to a rule failure and `Spec::not(...)` turned it into approval. A property whose value is `null` is still a rule failure.
- **Comparison and equality specifications refuse incompatible candidate types.** `GreaterThan`/`LessThan` (and `atLeast`, `atMost`, `between`), the date leaves (`before`, `after`, `at`, `beforeOrAt`, `afterOrAt`, `between`, `isToday`, `isPast`, `isFuture`) and the strict `Equal`/`NotEqual` (`equalTo`, `isTrue`, `isFalse`, `in`) now throw `Specifications\Exceptions\IncompatibleTypeException` instead of letting PHP coerce: a string candidate against a numeric threshold, an object against a string, `"5"` against `5`, `1` against `true`. Numeric strings are not coerced; `int` and `float` are distinct types for strict equality. Under `evaluate()` this becomes an error result. Subsumption (`isGeneralizationOf`, `isDisjointWith`) between mixed-type specifications returns `false` without throwing. **Breaking for** code that relied on loose coercion: use `looselyEqualTo()`.
- **`ISpecification::equals()` is now part of the contract.** `AbstractSpecification` provides a structural default (same class and equal parameters; nested specifications compared through `equals()`, dates by instant, arrays element by element, scalars strictly). Custom specifications that extend `AbstractSpecification` get it for free; classes implementing `ISpecification` directly must add it.
- **Dynamic Rule Engine binds every compiled rule to its catalog definition.** Specifications returned by rule handlers are wrapped in `Engine\RuleBoundSpecification` by `DynamicSpecificationEngine::compileSpecification()`: every failure now carries the rule's `acao`, `fundamento_legal`, `regra`, `tipo_regra`, `nome_regra` and `prioridade` in its metadata, with handler-provided data taking precedence. A raw specification (no `withCode()`/custom failure) is reported once per rule, with the rule code and `mensagem_violacao`; technical messages are kept in `metadata['mensagens_originais']`. Previously a WARN/LOG rule whose handler did not copy the action by hand was triaged as BLOCK and `getLegalBases()` came back empty. The SQL, TCriteria and ALinq visitors translate the compiled specification transparently (they unwrap it), so `Spec::toSql($engine->compileSpecification(...))` keeps working.
- **Evaluation errors always block.** `RuleEngineVerdict` classifies a failure produced by an evaluation error (`SpecificationResult::error()`) as blocking regardless of the configured rule action, and exposes it via `hasEvaluationErrors()`. `getFailureCodes()` now returns one entry per failure (explicit `null` when a failure has no code) instead of silently dropping nulls. `isSatisfied()` is documented as "no failure of any action was recorded"; the operational gate is `hasBlockingErrors()` or the new `canProceed()`.
- **Document requirements declare their scope; the catalog matches on it, never on the group code.** `IDocumentRuleDefinition` now requires `getEscopo(): string` and `getCenario(): ?string`, mirroring the relational document matrix (scope is mandatory on the group, scenario is optional, the group code is an identifier only). `DocumentRuleDefinition` takes `escopo` as its third constructor parameter and refuses an empty one (`InvalidArgumentException`); `fromArray()` requires the `escopo` key and reads an optional `cenario`. `InMemoryRuleCatalog::findDocumentRules()` matches exactly on scope and scenario, so documents can no longer leak between scopes (`contrato` vs `contratos_x`, `sinistro_ocupado` vs `sinistro_desocupado`, two scopes sharing a scenario name): the former guesswork on `grupo_codigo` is gone. **Breaking for** every caller that builds `DocumentRuleDefinition` (positional calls shift by one argument and fail with a `TypeError`; records without `escopo` throw) and for custom `IDocumentRuleDefinition` implementations, which must add the two getters.
- **Rule catalog scenario semantics.** `IRuleCatalog::findRules()`/`findDocumentRules()` with a `null` scenario now return scope-global rules and documents only, never every scenario at once.
- **Document matrix semantics.** A document whose conditional guard does not hold is *not applicable*: it leaves the count of `ANY`/`ONE_OF_SET` sets instead of counting as present (a `ONE_OF_SET` with one conditional document used to reject candidates holding the right document and accept candidates holding none). `ANY`/`ONE_OF_SET` rules without `codigo_set_alternativas` are now refused at compilation with `Engine\Exceptions\MissingAlternativeSetException` (the relational catalog already forbids that shape; previously each such rule became a set of one document, which degenerated into `ALL`). A failing set emits one aggregated failure (`DOC_SET_<KEY>`) listing the accepted documents (`metadata['documentos_aceitos']`, `['codigos']`) instead of one failure per document. An unsupported guard expression now throws `Engine\Exceptions\InvalidConditionalExpressionException` at compilation instead of silently requiring the document.

### Fixed
- **TCriteria Builder**: `equalIgnoreCase` and `wildcardExpressionMatcherIgnoreCase` leaves now reach the database as `UPPER(col) LIKE UPPER(value)` (and `NOT LIKE` under negation), also in prepared mode and at any nesting depth. Previously the Adianti `TCriteria::dump()` reset the case-insensitive flag of every child filter to its own default (`false`), so those searches were silently case-sensitive on PostgreSQL, Oracle, Firebird and SQLite. The visitor now emits `Criteria\TCaseInsensitiveFilter` (a `TFilter` whose flag cannot be switched off) for those leaves; sensitive sibling filters are unaffected. The Adianti test stub now mirrors the real flag propagation, and the suite additionally verifies the translation against the real Adianti classes in a child process when they are available next to the repository.
- **Partitioned repositories no longer orphan entities when sibling partitions share a class.** `addPartition()` treated two leaves of the same class as equivalent (the fallback compared class name and string form, and the string form is the class name), replaced the existing partition and dropped the entities that did not satisfy the new specification. Equivalence is now `equals()`; `collectPartitions()` no longer throws for leaves without a custom `equals()`.
- **`SingleFileRepository` no longer loses updates between processes or instances.** The exclusive lock was taken on the document itself, which `rename()` replaces with a new inode, and each instance stored the whole map it had loaded once. Locks now live in a stable `<document>.lock` file next to the document, and in `ReadWrite` mode every mutation re-reads the document under the lock before writing the merged map. Snapshot/WriteOnly/MemoryOnly modes keep writing the whole map on `store()`/`close()`.

### Added
- `SpecificationResult::error()`, `SpecificationResult::$isError`, `SpecificationResult::$exception` and `SpecificationResult::withLeadingFailures()`.
- Opt-in loose equality: `Spec::looselyEqualTo($value)`, `looselyEqualTo()` DSL function, `IComparisonSpecificationFactory::looselyEqualTo()` and `LooseEqualSpecification` (`==` semantics; extends `EqualSpecification`, so SQL, TCriteria and ALinq visitors translate it as plain equality).
- `Specifications\Comparison\TypeCompatibility` (type guards) and `Specifications\Exceptions\IncompatibleTypeException`.
- `Engine\RuleBoundSpecification` (with `getInnerSpecification()` and `getRule()`), `RuleEngineVerdict::canProceed()` and `::hasEvaluationErrors()`.
- `IDocumentRuleDefinition::getEscopo()` / `::getCenario()`; `DocumentRuleDefinition` `escopo` and `cenario` constructor parameters and `fromArray()` keys.
- `Engine\DocumentLeafSpecification` and `Engine\DocumentSetSpecification`, the named building blocks of the document matrix; `DocumentGroupSpecificationBuilder::resolveSetKey()` and `::createAnySetSpecification()` hooks; `Engine\Exceptions\MissingAlternativeSetException`.
- `Criteria\TCaseInsensitiveFilter`.

## [1.1.2] - 2026-10-07

### Security
- **SQL Query Visitor**: column identifiers are now validated against a strict grammar before reaching the `WHERE` clause. Plain or dot-qualified identifiers are quoted by the dialect; simple function calls over identifiers (`LOWER(name)`, `COALESCE(c.nick, c.name)`) are preserved; anything else throws `Sql\Exceptions\UnsafeIdentifierException`. Previously, any name containing parentheses was emitted raw, which allowed SQL injection through the property name or a `FieldMapper` result. **Breaking for** field mappers that returned arbitrary SQL expressions (`CASE WHEN ...`): build those clauses outside the visitor.
- **TCriteria Builder**: values that the Adianti `TFilter` emits as raw SQL even in prepared mode (starting with `(SELECT`, containing `{session.`, starting with `NOESC:`) are now refused with `Criteria\Exceptions\UnsafeCriteriaValueException` before the `TFilter` is built, for every leaf including `IN` lists and De Morgan inversions. Values are data, never SQL: a value that the target engine would interpret as SQL is rejected instead of forwarded. The Adianti test stub now mirrors the real `TFilter::transform()` for these shapes.
- **SingleFileRepository**: the `.bin` envelope is now read with `allowed_classes => false`. Previously it was read with `allowed_classes => true`, so an object placed in the envelope was instantiated (running `__wakeup`/`__destruct`) before the `PhpNativeEntitySerializer` whitelist applied. Entities are still reconstructed through the whitelist; existing `.bin` files remain readable.
